## 네트워크 보안 단답형
##### 무선랜 CSMA/CA 통신 <mark style="background:#ffff88"><strong><font color="#ff0000">RTS, CTS</font></strong></mark>
24.2 기사
- 무선랜 CSMA/CA 통신에서는 모든 통신에 대해 연결 타임아웃(연결 지속시간)이 적용된다. 이때 연결 타임아웃 설정이 어느 신호(프레임)에 포함되는지 보기에서 2개 고르시오.
- CTS, DATA, RTS, SYN, ACK, RST
- 무선랜 CSMA/CA 통신에서는 충돌 회피(Collision Avoidance)를 위해 RTS(Request To Send)/CTS(Clear To Send) 방식을 이용한다. 
- 송신을 원하는 노드가 RTS 신호를 수신 노드에 보내면 수신 노드는 통신이 가능한 경우에만 CTS 신호를 요청한 노드를 포함하여 모든 노드에 보내 특정 노드와 통신한다는 사실을 알리게 된다. 
- 이때 RTS/CTS 신호에는 프레임 전송에 얼마나 시간이 걸리는지를 나타내는 정보(NAV : Network Allocate Vector, 연결 지속시간)가 포함되어 있어 해당 시간 동안 다른 노드의 접근을 막아줄 수 있다.

##### 스위치(Switch) 장비의 LAN 스위칭(Switching) 방식(기법) 3가지
23.4 기사 25.4 기사
- LAN 스위칭(Switching) : 스위치에 입력된 이더넷 프레임을 어떤 방식으로 출력 포트에 전달할지를 결정하는 전송 방식을 의미한다. 
- 대표적인 스위칭 방식으로는 <mark style="background:#ffff88"><strong><font color="#ff0000">Store-and-Forward </font></strong></mark>방식, <mark style="background:#ffff88"><strong><font color="#ff0000">Fragment-Free</font></strong></mark> 방식, <mark style="background:#ffff88"><strong><font color="#ff0000">Cut-Through</font></strong></mark> 방식이 있다.

##### ARP 요청 메시지의 이더넷 프레임 목적지 주소
19.2 기사 23.1 기사
- ARP(Address Resolution Protocol) 프로토콜은 논리적인 IP 주소를 물리적인 MAC 주소로 변환해 주는 프로토콜로 ARP 요청 메시지와 ARP 응답 메시지로 동작한다. 물리적인 주소(MAC 주소)를 얻기 위한 요청 메시지를 보낼 때 요청 이더넷 프레임(Ethernet Frame)의 목적지 주소가 어떻게 설정되는지 해당 주소 표기법으로 작성하시오.
- ARP 프로토콜은 로컬 네트워크의 모든 호스트에게 대상 IP를 가진 호스트의 MAC 주소를 질의하는 요청 메시지를 만들어 브로드캐스트(broadcast) 방식으로 요청하고 대상 IP가 설정된 호스트는 자신의 MAC 주소를 담은 응답 메시지를 만들어 요청한 호스트에게 유니캐스트(unicast) 방식으로 응답한다.
- 따라서 요청 메시지를 전송할 때는 프레임의 목적지 MAC 주소 필드에 브로드캐스트 주소인 <mark style="background:#ffff88"><strong><font color="#ff0000">FF:FF:FF:FF:FF:FF</font></strong></mark>가 설정된다.

##### <mark style="background:#ffff88"><strong><font color="#ff0000">ARP 스푸핑(Spoofing)</font></strong></mark>
19.1 기사 22.1 기사
- 공격자가 **다른 호스트의 MAC 주소를 자신의 MAC 주소로 위조**한 응답 메시지를 만들어 지속해서 희생자에게 전송하면 희생자의 캐시(Cache) 정보가 조작되어 희생자가 조작된 호스트로 패킷을 전송할 때 캐시에 저장된 조작된 MAC 주소인 공격자에게 전송된다.

##### <mark style="background:#ffff88"><strong><font color="#ff0000">스위치 재밍(Switch Jamming)</font></strong></mark> 또는 <mark style="background:#ffff88"><strong><font color="#ff0000">MAC 플러딩(Flooding) </font></strong></mark>공격
13.2 기사
- 다음은 스위칭 환경에서 스니핑 공격과정을 설명하고 있다. 이에 해당하는 공격 기법을 쓰시오.
- 일반적으로 스위치 장비들은 MAC 주소 테이블이 가득 차게 되면 모든 네트워크 세그먼트 트래픽을 브로드캐스트하는 특징을 가지고 있다. 따라서 **공격자는 위조된 MAC 주소를 지속해서 네트워크에 흘림으로써 스위칭 허브의 주소 테이블을 오버플로우시켜 허브처럼 동작하게** 하여 해당 네트워크 세그먼트의 데이터를 스니핑할 수 있게 된다. 이는 일반적인 스위치 장비가 보안 원리의 하나인 "Fail Close"를 따르지 않기 때문이다.
- 결국 공격자가 만들어 낸 임의의 ARP 패킷의 MAC 주소가 스위치의 주소 테이블을 오버플로우 시키게 되는 것이 공격 성공의 주요 요인이다.

##### 서브넷 마스크의 2진수 표기 (255.255.255.192)
24.1 기사
- IP 주소가 200.100.50.25(C 클래스)이고 서브넷 마스크(subnet mask)가 255.255.255.192일 때 서브넷 마스크를 2진수로 작성하시오.
- 11111111.11111111.11111111.11000000
- 대상 네트워크의 IP 주소 범위 : 200.100.50.00000000(0) ~ 200.100.50.00111111(63)
- 대상 네트워크에서 호스트에 할당할 수 있는 IP 주소 개수 : $2^6 - 2 = 62$ (네트워크 주소 및 브로드캐스트 주소 제외)
- IP주소 AND 서브넷 마스크 = 네트워크 주소
- 대상 네트워크의 네트워크 주소 : 200.100.50.00000000(0)
* 대상 네트워크의 브로드캐스트 주소 : 200.100.50.00111111(63)

##### IP 단편화(Fragmentation)
17.1, 기사
- IP 단편화(Fragmentation)는 다양한 네트워크 환경에서 IP 패킷의 효율적인 전송을 가능하게 하는 패킷 분할 기법이다. IP 데이터그램을 단편화할 때 tcpdump의 내용 중 다음 A, B, C가 의미하는 바를 쓰시오.
```
04:05:493961718 < 10.10.10.1 > 10.10.10.100: (frag 22666:48@2960+) (ttl 128)
A : 22666
B : 48
C : 2960+
```
- IP 단편화 관련 tcpdump의 출력 형식은 'frag id:size@offset[+]' 이다. id는 단편화 전 원본 IP 데이터그램을 식별하기 위한 단편 ID를 의미하고, size는 ip 헤더를 제외한 단편의 크기로 바이트 단위로 표시한다. offset은 단편의 상대위치를 나타내며 +는 추가 단편이 있음을 의미하고 +가 없으면 마지막 단편을 의미한다.
- A : 22666은 <mark style="background:#ffff88"><strong><font color="#ff0000">단편(Fragment) ID</font></strong></mark>를 의미한다.
- B : 48은 <mark style="background:#ffff88"><strong><font color="#ff0000">IP 헤더를 제외한 단편 크기</font></strong></mark>(바이트 단위)를 의미한다
- C : 2960+는 <mark style="background:#ffff88"><strong><font color="#ff0000">단편의 상대위치(Offset)가 2960이고 추가 단편이 있음(+)을 의미</font></strong></mark>한다.

##### <mark style="background:#ffff88"><strong><font color="#ff0000">세션 하이재킹(Session Hijacking) 공격</font></strong></mark>
22.1 기사 24.1 기사
- 공격 대상 시스템에 접근할 수 있는 인증 정보(예: 아이디와 패스워드)를 모를 경우, 인증이 완료되어 정상적인 통신을 하는 **사용자의 세션을 가로채 별도의 인증 없이 가로챈 세션으로 통신하는 공격 행위**를 말한다.
- 세션 하이재킹(Session Hijacking) 공격은 '공격자가 인증이 완료된 정상적인 사용자 세션을 중간에 가로채서 별도의 인증 작업 없이 정상적인 사용자로 위장(가장)하여 가로챈 세션으로 통신하는 행위'를 말한다. 정상적인 사용자의 인증이 완료된 세션을 가로채기 때문에 강력한 사용자 인증기법(예: 일회성 패스워드(OTP), 시도/응답 기법 등)을 사용한다고 해도 이를 무력화할 수 있는 특징이 있다. 주요 공격 기법을 살펴보면 다음과 같다.
* TCP 세션 하이재킹(Session Hijacking) 공격
	* TCP의 세션 관리 취약점을 이용한 공격으로 인증된 사용자의 세션 관리정보(출발지 IP/Port, Sequence Number 등)로 위조하여 TCP 세션을 가로채는 공격을 말한다.
* HTTP 세션 하이재킹(Session Hijacking) 공격
	* HTTP의 세션 관리 취약점을 이용한 공격으로 인증된 사용자의 HTTP 세션 ID를 탈취하여 인증된 사용자로 위장하여 서버에 접근하는 공격을 말한다.
