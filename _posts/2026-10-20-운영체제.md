## 프로세스와 스레드
### 01 프로세스
#### 프로세스 정의
- 실행 중인 프로그램
- 실행 가능한 프로그램이 메모리에 적재되어 운영체제의 관리를 받으며 실행되는 상태로, 실행에 필요한 메모리 영역을 사용한다
- 프로세스는 반드시 한 개의 PCB(Process Control Block)와 연결된다
- 디스패치가 가능한 대상
	- 디스패치(dispatch) : 운영체제가 준비 상태의 프로세스에 CPU를 할당하여 실행 상태로 전환하는 것.

#### 프로세스의 일반적인 메모리 구조
- 프로그램은 컴파일한 코드와 초기화 전역변수, 문자열과 문자열 상수 등 정적 데이터를 포함하는 정적 개체이다.
- 프로세스는 프로그램 카운터나 레지스터처럼 어떤 자원을 사용하는지 관련 정보가 들어있는 동적인 개체이다.
![303](/assets/images/memory_layout%201.png)
- 스택(stack)
	- 데이터를 일시적으로 저장하는 영역
	- 지역변수, 호출한 함수의 반환 주소, 반환 값, 매개변수 등에 사용.
	- 함수를 호출할수록 커지고 반환하면 줄어든다.
- 힙(heap)
	- 코드 영역과는 별도로 유지되는 자유영역
	- 동적으로 메모리를 할당하려고 프로그램 실행 중 시스템 호출을 사용했다가 해제하는 방법으로 활용
- 데이터(data)
	- 프로그램 가상주소 공간
	- 전역변수나 정적변수를 저장하거나 할당하고 실행하기 전에 초기화한다.
		- 변수 초기화: 프로그램 실행 시 전역변수나 정적변수에 초기값을 설정한다.
- 코드(code)
	- 실행 명령을 포함하는 메모리거나 목적 파일에 있는 프로그램 영역
	- 프로그램을 시작할 때 프로세서가 디스크에서 읽어 실행하는 컴파일한 프로그램을 저장한다.

### 02 프로세스 종류
- 부모 프로세스
- 자식 프로세스 : 부모 프로세스에 의해 만들어지는 프로세스. 할 일이 끝나면 부모 프로세스에게 결과를 돌려주고 종료된다.
- 고아 프로세스 : 자식 프로세스가 아직 실행 중인데 부모 프로세스가 먼저 종료되어 버린 경우
- 좀비 프로세스 : 자식 프로세스가 실행을 종료했는데 프로세스 목록에 남아있는 경우

#### 1. 역할에 따른 분류
- 시스템(커널) 프로세스
	- 모든 시스템 메모리와 프로세스 명령에 엑서스할 수 있는 프로세스
	- 프로세스 실행 순서를 제어하거나 다른  사용자 및 커널(운영체제) 영역을 침범하지 못하게 감시하고, 사용자 프로세스를 생성하는 기능을 한다.
- 사용자 프로세스
	- 사용자 코드를 수행하는 프로세스
	- 사용자 응용프로그램을 수행하는 프로세스

#### 2. 병행 수행 방법에 따른 분류
- 독립 프로세스
	- 다른 프로세스에 영향을 주지 않거나 다른 프로세스의 영향을 받지 않으면서 수행하는 병행 프로세스
- 협력 프로세스
	- 다른 프로세스에 영향을 주거나 다른 프로세스에서 영향을 받는 병행 프로세스

### 03 프로세스 상태
#### 1. 프로세스 상태
  ![333](/assets/images/process_state_diagram.png)
1. 생성 : 프로세스의 작업 공간이 메인 메모리에 생성되고 운영체제 내부에 프로세스의 실행정보를 관리하기 위한 프로세스 제어 블록(PCB)이 만들어지는 상태  
2. 준비 : 프로세서에게 할당되기를 기다리는 상태  
3. 실행 : 프로세서를 점유하여 명령들이 실행되는 상태  
4. 대기 : 프로세스가 어떤 이벤트(입출력 종료와 같은 외부 신호)가 일어나기를 기다리는 상태  
5. 완료 : 프로세스의 수행이 끝난 상태  

#### 2. 프로세스 상태 변환  
1. 준비 → 실행(dispatching)
- 준비 상태의 프로세스는 디스패치(dispatcher)에 의해 프로세서가 부여되면 실행상태가 된다.  
2. 실행 → 준비(time run out)
- 어떤 프로세스가 프로세서를 계속 독점하는 것을 방지하기 위해 운영체제는 인터럽트 클록을 두어서 지정된 시간 동안만 프로세스가 프로세서를 점유하도록 한다.  
3. 실행 → 대기(block)
- 실행상태의 프로세스가 지정된 시간 이전에 입출력 연산 등을 필요로 할 경우 그 프로세스는 스스로 프로세서를 양도하게 된다.  
4. 대기 → 준비(wake up)
- 입출력 작업이 끝났을 때, 대기 상태의 프로세스는 준비 상태로 변환한다.  

- 프로세스의 종료  
	- 프로세스가 마지막 명령을 실행하며 종료하며 운영체제에 프로세스의 삭제를 요청한다. 
	- 일괄처리 환경에서는 인터럽트를 발생하거나 시스템 호출로 중단 명령을 전달하여 프로세스를 종료한다.  
	- 대화형 환경에서는 사용자가 로그오프(log-off)하거나 터미널을 닫으면 프로세스를 종료한다.  
	- 이외 오류로 프로세스를 종료할 수 있다.

- 리눅스 시그널 종류  
	- SIGHUP : 로그오프와 같이 터미널에서 접속이 끊긴 경우  
	- SIGINT : Ctrl + C 입력하여 실행을 중지한 경우  
	- SIGQUIT : Ctrl + ₩ 입력하여 실행을 중지한 경우  
	- SIGILL : 잘못된 명령을 사용한 경우  
	- SIGTRAP : 트랩 요청이 발생한 경우  
	- SIGABRT : abort 명령을 사용한 경우  
	- SIGKILL : 프로세스를 강제로 종료시키는 경우  
	- SIGTERM : 가능한 프로세스를 정상 종료시키는 경우  
	- SIGCHLD : 자식 프로세스가 종료되는 경우 부모 프로세스에게 전달  
	- SIGCONT : 정지된 프로세스를 다시 실행시키는 경우  
    - SIGSTOP : 터미널에서 정지 요청이 입력된 경우

### 04 프로세스 제어 블럭(PCB, Process Control Block)
- 운영체제에 특정 프로세스에 대한 중요한 정보를 제공해 주는 데이터 블록이다.  
- 프로세스를 생성할 때 만들어지며 주기억장치에 유지되며 운영체제 내에서 한 프로세스의 존재를 정의한다. 프로세스의 실행이 종료되면 같이 삭제된다.  
- 인터럽트 처리, 자원할당, 스케줄링 등을 수행하는 운영체제의 모든 모듈에 의해 판독되고 수정될 수 있다.

#### PCB 구성요소
- **프로세스 식별자** : 각 프로세스의 고유 식별자
- **프로세스 상태** : 생성, 준비, 실행, 대기, 중단 등 상태 표시
- **프로그램 카운터** : 프로세스를 실행하는 다음 명령의 주소 표시
- **레지스터 저장 영역**
	- 누산기, 인덱스 레지스터, 스택 포인터, 범용 레지스터, 조건 코드 등의 정보
	- 컴퓨터 구조에 따라 수나 형태가 다르다.
	- 인터럽트가 발생하면 프로그램 카운터와 함께 저장한다.
- **프로세서 스케줄링 정보** : 프로세스의 우선순위, 스케줄링 큐의 포인터, 기타 스케줄 매개변수
- **계정 정보** : 프로세서 사용시간, 실제 사용시간, 사용 상한시간, 계정번호, 작업이나 프로세스 번호 등
- **입출력 상태 정보** : 특별한 입출력 요구 프로세스에 할당된 입출력장치, 열린 파일 리스트 등
- **메모리 관리 정보** : 운영체제가 사용하는 메모리 시스템에 따른 상한·하한 레지스터(경계 레지스터), 페이지 테이블이나 세그먼트 테이블 값

#### 프로세스 생성 시 필요한 세부 작업  
1. 새로운 프로세스에 **프로세스 식별자를 할당**한다.  
2. 프로세스의 모든 구성 요소를 포함할 수 있는 **주소 공간과 프로세스 제어 블록 공간을 할당**한다.  
3. **프로세스 제어 블록을 초기화**한다. 프로세스 상태, 프로그램 카운터 등 초기화, 자원 요청, 프로세스 제어 정보(우선순위) 등을 포함한다
	- PCB 초기화: 프로세스 실행 및 관리를 위해 상태, 프로그램 카운터, 우선순위 등의 초기 정보를 설정하는 과정.
4. **해당 준비큐에 삽입**한다.

### 05 문맥교환(Context Switching)![context_switching 1](/assets/images/context_switching%201.png)
- 프로세서를 다른 프로세스로 전환하려면 이전의 프로세스 상태 레지스터 내용을 보관하고, 다른 프로세스의 레지스터들을 적재하는 과정을 말한다.
- 프로세스가 '준비 → 실행', '실행 → 준비', '실행 → 대기' 상태로 변환할 때 발생한다. 
- 문맥교환은 모두 **과부하(overhead)가 발생**한다.  
- 운영체제에서 문맥교환은 자주 발생하므로 가능한 효율적으로 구현되어야 하는데 이를 위해 **스레드**(thread)를 사용한다.
### 06 스레드(Thread)
#### 1. 스레드의  개념
- **프로세스는 자원과 제어로** 특성을 **구분**할 수 있는데 이 중 **제어만 분리한 실행 단위를 스레드**(thread)라 한다.
- 프로세스 하나는 스레드 한 개 이상으로 나눌 수 있다.  
- 스레드들은 프로세스의 직접 실행 정보를 제외한 나머지 프로세스 관리 정보를 공유한다.  
	- 프로그램 카운터(PC)와 스택 포인터(SP) 등을 비롯한 스레드 실행 환경 정보(문맥 정보), 지역 데이터, 스택을 독립적으로 갖는다.  
	- **코드, 전역 데이터, 힙을 다른 스레드와 공유한다.**![thread_structure 2](/assets/images/thread_structure%202.png)
- **응용 프로그램에는 하나 이상의 프로세스**가 있고, **프로세스에는 한 개 이상의 스레드**가 있다.  
- **같은 프로세스의 스레드들은 동일한 주소 공간(코드,데이터,힙)을 공유**한다.
- **스레드도 프로세스처럼 준비, 실행, 대기, 종료 상태가 있다.**

#### 2. 스레드의 이점
  - **프로세스의 자원과 메모리 공유 가능** : 스레드들이 프로세스 자원 하나와 메모리를 공유하므로 응용 프로그램 하나가 동일한 주소 공간에서 스레드를 여러 개 실행하여 시스템 성능을 향상시킬 수 있다.  
- **오버헤드 감소** : 프로세스를 생성하는 것보다 스레드를 생성하여 문맥 교환을 수행하면 오버헤드가 줄어든다.  
- **다중처리(멀티 프로세싱)로 성능과 효율 향상** : 각 스레드를 여러 프로세서에서 병렬로 실행하여 성능과 효율성을 높일 수 있다.

#### 3. 단일 스레드와 다중 스레드![thread_diagram_ko 3](/assets/images/thread_diagram_ko%203.png)
  
- 프로세스의 모든 스레드들은 그 프로세스의 자원과 상태를 공유하게 되고 또한 같은 주소 공간에 존재하며 동일한 데이터에 접근한다.

##### 단일 스레드  
프로세스 하나에 스레드 한 개를 실행하는 전통적인 방법으로 아직 스레드 용어가 탄생하기 전이라 개념이 불확실하다. 도스가 대표적인 예이다.  
##### 다중 스레드  
- 동일 프로세스의 스레드는 자원을 공유하므로 자원 생성과 관리의 중복성을 최소화하여 실행 능력을 향상시킬 수 있다.  
- **각 스레드는 커널이 개입하지 않고도 독립적으로 실행할 수 있어** 서버에서 많은 요청을 효과적으로 처리할 수 있다.
- 프로세스보다 **스레드를 생성하는 것이 더 빠르고**, **동일한 프로세스에 있는 스레드 간의 교환이나 종료도 더 빠르다.**  
- **프로그램을 변경하지 않고 스레드를 병렬로 처리**하여 효율을 극대화할 수 있다.  
- 스레드별 실행 환경 정보는 독립적으로 유지하지만, 코드·데이터·힙 영역을 공유하므로 프로세스 간 문맥 교환보다 **동일 프로세스 내 스레드 간 문맥 교환의 오버헤드가 작다.**

## 03 병행 프로세스
### 01 병행 프로세스
- **프로세서(CPU) 하나는 한 번에 프로세스 하나만 실행할 수 있다.**  
	- **프로세서(Processor)** : 프로그램 명령어를 해석하고 실행하는 하드웨어 장치(**=CPU**)
- **병행 프로세스** : **운영체제가 프로세서를 빠르게 전환하여 마치 프로세스 여러 개를 동시에 실행하는 것처럼 보이게 하는 것**
#### 병행 프로세스의 동기화 및 상호 배제를 위한 조건
- **공유 자원을 배타적으로 사용**
- 병행 프로세스들 사이에는 **동기화**가 이루어져야 한다.  
- 두 프로세스 사이에는 데이터 교환을 위한 **통신**이 이루어져야 한다.  
- 프로세스들은 동시에 수행되는 **다른 프로세스들의 실행 속도와 관계없이 항상 일정한 실행 결과가 보장**하도록 결정성을 확보해야 한다.  
	- 결정성(Determinism): 같은 조건에서 실행했을 때 결과가 일정하게 결정되는 성질.
- **교착상태를 해결**해야 하며 **병행 프로세스들의 병렬 처리 능력을 극대화**한다.
- 병행 **프로세스를 수행하는 과정에서의 상호배제를 보장**한다.
	-  상호배제 : 어떤 프로세스가 작업을 실행 중일 때 나머지 프로세스는 그것과 관련된 작업을 수행할 수 없도록 하는 것.

### 02 상호 배제와 동기화
#### 1. 임계영역(Critical Section)
- **임계자원**: **여러 프로세스가 공유**하며, **동시에 접근할 경우 문제**가 발생할 수 있는 자원.
- **임계영역**: **공유 자원에 접근하는 코드 영역**으로, **상호 배제가 필요**한 부분.
- 프로세스가 공유 데이터를 액세스하는 동안 그 프로세스는 임계영역 내에 있다고 한다. 
- 임계영역에는 한 순간 반드시 단 하나의 프로그램만이 허용된다.  
- 임계영역 내 작업은 가능한 한 신속하게 수행
	- 임계영역의 실행 시간이 길어지면 다른 프로세스들이 자원을 사용하지 못하고 대기하는 시간이 길어지기 때문
- 프로세스는 임계영역 내에서 대기(block)되어서는 안 되며 무한루프에 빠지지 않아야 한다
##### 임계영역 문제를 해결하기 위한 조건  
1. **상호배제** : 프로세스 P가 임계영역을 수행 중일 때 다른 어떤 프로세스도 임계영역을 수행할 수 없다.  
2. **진행** : 임계영역을 실행 중인 프로세스가 없고 여러 프로세스가 진입을 원할 때, 잔류영역에 있지 않은 프로세스 중 하나를 선택하며 선택이 무한정 지연되어서는 안 된다.
	- 잔류영역(Remainder Section): 프로세스가 임계영역에서 작업을 마친 후, 다음 임계영역에 진입하기 전까지 수행하는 나머지 코드 영역.
3. **제한된 대기** : 한 프로세스가 임계영역 진입을 요청한 후 허용되기까지, 다른 프로세스들이 임계영역에 진입할 수 있는 횟수에는 제한이 있어야 한다. 특정 프로세스가 임계영역에 무한정 들어가지 못하는 상황을 방지하기 위해.

##### 상호배제 방법  -> 정리
1. **데커의 알고리즘**(Dekker's algorithm) : 두 프로세스가 서로 통신하기 위해 **공유메모리**를 사용하여 충돌 없이 단일 자원을 공유할 수 있도록 허용한다.  
2. **TestAndSet 명령어** : 기계를 비교하거나 단어 내용을 검사, 수정하는 특별한 하드웨어 명령어(TestAndSet)를 사용한다.  
3. **세마포어**(Semaphore) : 세마포어 변수 값이 true일 때 프로세스 상태를 확인하는 동기화 도구이다.  
4. **모니터**(Monitor) : 공유 자원과 이것의 임계 영역을 관리하는 병행프로그래밍 구조이다.

#### 2. 프로세스 동기화의 대기 방식 -> 다시 정리
##### BusyWaiting(=바쁜 대기, 능동 대기)
- 조건이 충족될 때까지 반복적으로 확인하면서 대기.
- 임계 영역에 들어갈 수 있을 때까지 아무 작업도 하지 않고 임계 영역에 접근이 가능한지 무한으로 검사
- 계속 CPU를 사용

##### Blocking(=수면 대기)
- 조건이 충족될 때까지 대기 상태로 전환
- 대기 중에는 CPU를 사용하지 않음

##### 스핀락(Spinlock)
- 잠금을 획득할 때까지 반복적으로 확인하는 동기화 기법. 비지 웨이트 방식으로 대기함.

##### 슬립(Sleep)
- 일정 시간 또는 조건이 충족될 때까지 실행을 중단하고 대기함.

#### 3. 세마포어(Semaphore)![Pasted image 20261021160549](/assets/images/Pasted%20image%2020261021160549.png)
- 여러 프로세스나 스레드가 **공유 자원에 접근하는 순서를 제어**하고, **동기화를 수행하기 위해 사용**하는 정수형 변수.
- S = 1 이면 임계영역 실행 중인 프로세스 없음
- S = 0 이면 임계영역 실행 중인 프로세스 존재
- 잘못 사용하면 교착상태나 기아 현상이 발생할 수 있다
##### 기본 동작
``` 
P(S):
	while S <= 0 do no-op;
	S = S - 1
V(S):
	S = S + 1	
```
- **P 연산(wait)** : 자원을 사용하기 위해 세마포어 값을 감소시키고, 자원이 없으면 대기 (자원 획득)
- **V 연산(signal)** : 자원 사용이 끝났음을 알리고 세마포어 값을 증가시키거나 대기 중인 프로세스를 깨움 (자원 반환 , 대기 프로세스의 실행 허용)
	- P와 V 연산은 **원자적으로 수행**되어야 한다
		- 원자적 수행(Atomic Operation): 하나의 연산이 중간에 중단되거나 다른 프로세스에 의해 간섭받지 않고, 하나의 작업 단위로 완전히 수행되는 것.
##### 세마포어 종류
- **이진 세마포어**(Binary Semaphore): 값이 0 또는 1이며, **상호 배제 및 프로세스 동기화**에 사용된다.
- **계수 세마포어**(Counting Semaphore): 여러 개의 동일한 자원에 대한 사용 가능 개수를 관리한다.

# 페이지 교체 알고리즘
### FIFO(First In First Out)
- 가장 먼저 들어와서 가장 오래 있었던 페이지를 교체하는 기법
### LRU(Least Recent Used)
- 최근에 **가장 오랫동안 사용하지 않은 페이지를 교체**하는 기법
### LFU(Least Frequently Used)
- **사용 빈도가 가장 적은 페이지를 교체**하는 기법.

# 스케줄링
- 프로세스가 생성되어 실행될 때 필요한 시스템의 여러 자원을 해당 프로세스에게 할당하는 작업
- 반환 시간 : 프로세스의 대기시간과 실행시간의 합
## 비선점 스케줄링
- 이미 할당된 CPU를 다른 프로세스가 강제로 빼앗아 사용할 수 없는 스케줄링 기법
- 일괄 처리 방식에 적합.
### FCFS(First Come First Service, 선입 선출) = FIFO
- 준비상태 큐에 도착한 순서에 따라 차례로 CPU를 할당하는 기법
### SJF(Shortest Job First)
- **준비상태 큐에서** 기다리고 있는 프로세스들 중에서 **실행 시간이 가장 짧은 프로세스**에게 먼저 CPU를 할당하는 기법.
- 가장 적은 평균 대기 시간을 제공하는 최적 알고리즘.
### HRN(Highest Response-ratio Next)
- 대기 시간과 서비스(실행) 시간을 이용하는 기법
- 우선 순위를 계산하여 그 숫자가 갖아 높은 것부터 낮은 순으로 우선순위가 부여.
- $우선순위 계산식 = (대기시간 + 서비스 시간)/서비스 시간$
## 선점 스케쥴링
- 하나의 프로세스가 CPU를 할당받아 실행하고 있을 때 우선순위가 높은 다른 프로세스가 CPU를 강제로 빼앗아 사용할 수 있는 스케줄링 기법.
### RR(Round Robin)
- **준비 상태 큐의 프로세스**들을 **시간 할당량**(Time Slice, Quantum) **동안만 실행**하고, 실행이 완료되지 않으면 큐의 뒤로 보내 다음 프로세스에게 CPU를 할당하는 기법.
- 시분할 시스템을 위해 고안.
- 할당되는 시간이 클 경우 FCFS 기법과 같아지고, 할당되는 시간이 작을 경우 문맥 교환 및 오버헤드가 자주 발생되어 요청된 작업을 신속히 처리할 수 없음.
### SRT(Shortest Remaining Time)
- **현재 실행 중인 프로세스의 남은 시간**과 **준비상태 큐에 새로 도착한 프로세스의 실행 시간을 비교**하여 **가장 짧은 실행 시간을 요구하는 프로세스에게 CPU를 할당**하는 기법.
- 시분할 시스템.
