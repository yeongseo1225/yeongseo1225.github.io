## 운영체제 개요
### 01 운영체제 개요
- **컴퓨터 시스템의 4가지 구성요소**
	- 하드웨어
	- 운영체제(OS)
	- 응용 프로그램
	- 사용자

- **커널(Kernel)**
	- 운영체제의 핵심 부분으로, **메모리에 상주**하면서 CPU, 메모리, 프로세스, 입출력 장치 등 **시스템 자원을 관리**하고, **응용 프로그램 실행에 필요한 서비스를 제공**하며 **하드웨어와 소프트웨어 간의 상호작용을 제어**하는 프로그램.

#### 1. 운영체제의 정의
- 컴퓨터의 **하드웨어와 소프트웨어 자원을 관리**하고, 사용자와 컴퓨터 간의 **인터페이스를 제공**하는 **시스템 소프트웨어**

#### 2. 운영체제의 목적
##### 편리성
- 사용자에게 편리한 환경 제공
- 인터페이스 제공
##### 효율성
- 시스템 성능 향상을 지원
- **처리 능력(Throughput) 향상** : **일정시간동안 처리하는 작업량**을 증가시킴.
- **반환시간(Turn around Time) 단축** : 사용자가 작업을 **요청한 시점부터 결과를 얻을 때까지 걸리는 시간**을 줄임
	- 시분할 시스템과 온라인 시스템에서는 응답시간(response time)
	- 일괄처리 시스템에서는 반환시간(Turnaround Time)
- **신뢰도(Reliability) 향상** : 시스템이 주어진 문제를 정확하게 처리하고 **오류없이 작동하는 정도**를 높임
- **사용 가능도(Availiability) 향상** : 시스템이 **필요할 때 즉시 사용할 수 있는 정도**를 높임

##### 제어 서비스 향상
- 운영체제는 시스템을 확장하고 효율적으로 운영할 수 있도록 새로운 기능의 개발을 지원해야 한다.
- 입출력 장치의 동작을 관리·제어하고 시스템 오류를 예방하여 컴퓨터 자원을 여러 사용자에게 효율적으로 할당하고 관리해야 한다.

#### 3. 운영체제의 기능
##### 자원 관리  
- **주기억장치 관리**
	- 주기억장치의 사용 현황과 사용 중인 프로세스를 확인한다.
	- 주기억장치에 적재할 프로세스를 결정한다.
	- 주기억장치의 할당 및 회수 방법을 관리한다.
- **보조기억장치 관리**  
	- 보조기억장치의 빈 공간을 관리한다.
	- 데이터를 저장할 공간을 할당하고 회수한다.
	- 파일을 생성하고 삭제한다.
	- 저장 공간의 사용 현황을 관리한다.
- **프로세스 관리**
	- 프로세스와 스레드를 스케줄링한다.
	- 사용자 프로세스와 시스템 프로세스를 생성하고 제거한다.
	- 프로세스를 중지하고 재수행한다.
	- 프로세스 동기화 및 통신 방법을 제공한다.
	- 교착상태의 예방, 회피, 탐지 및 복구를 수행한다.
- **주변장치(입출력장치) 관리**
	- 입출력장치의 동작을 관리하고 제어한다.
	- 입출력 작업의 효율을 높이기 위해 버퍼링 및 스풀링 등의 기능을 제공한다.
	- 장치 드라이버를 통해 운영체제와 입출력장치 간의 상호작용을 지원한다.
- **파일(데이터) 관리**
	- 파일과 디렉터리를 생성하고 삭제한다.
	- 파일의 저장 위치와 접근을 관리한다.
	- 파일의 읽기, 쓰기 및 접근 권한을 관리한다.
	- 데이터를 보조기억장치에 저장하고 관리한다..

##### 시스템 관리  
- 시스템 보호(사용자 권한 부여)  
	- 프로그램, 프로세스 및 사용자의 시스템 자원 접근을 제어
	- 접근 권한 설정 및 데이터 암호화 등을 통해 시스템과 데이터를 보호
- 네트워킹(통신)
	- 컴퓨터 및 프로세스 간의 통신과 데이터 교환을 지원
	- 경로 설정, 연결 관리, 통신 규약 및 보안 등을 관리
- 명령 해석기(=Shell)
	- 사용자나 프로그램에서 대화형으로 입력한 명령어를 이해하고 실행하는 사용자와 운영체제의 인터페이스이다.

#### 운영체제 서비스
##### 부팅 서비스![booting_service_diagram_v2.png](/assets/images/booting_service_diagram_v2.png)

- **부팅**(booting) : 운영체제를 메인 메모리에 적재하는 과정
- **부트로더** : 하드 디스크와 같은 **보조기억 장치에 저장된 운영체제(커널)를 주기억장치(메인 메모리)에 적재하여 실행할 수 있도록 하는 프로그램.

##### 시스템 호출(system call)
- 시스템 호출은 실행 중인 프로그램과 운영체제 간의 인터페이스로, API(Application Programming Interface)라고도 한다.  
- 사용자 프로그램은 시스템 호출을 하여 운영체제의 기능을 제공받는다.  
- 시스템 호출에는 핵심 커널 서비스와 통신, 새로운 프로세스의 생성과 실행, 하드웨어 관련 서비스 등이 있다.  
- 시스템과 상호작용하는 동작은 대개 사용자 수준 프로세서에서는 사용할 수 없으나, 시스템 호출을 하여 운영체제에 서비스를 요청할 수 있다.

### 02 운영체제 유형별 특징
#### 다중프로그래밍 시스템(Multi-Programming System)  
- **하나의 CPU**에서 **여러 사용자 프로그램**을 **번갈아 실행**하여 동시에 실행되는 것처럼 처리하는 방식이다. 한 프로그램이 입출력 작업 등으로 CPU를 사용하지 않는 동안 다른 프로그램에 CPU를 할당하여 CPU 이용률을 높인다.
- 여러 프로그램을 메모리에 적재해야 하므로 **메모리 관리가 필요**하며, 실행할 프로그램을 선택하기 위한 **CPU 스케줄링이 필요**하다.

#### 시분할 시스템(Time Sharing System)  
- 다중 프로그래밍과 CPU 스케줄링을 이용하여 **CPU 시간을** 여러 사용자나 작업에 **짧은 시간 단위로 할당**함으로써 여러 작업이 동시에 실행되는 것처럼 처리하는 방식이다.
- 여러 작업이 메모리에 동시에 적재되므로 한 작업이 다른 작업의 데이터나 메모리에 무단으로 접근하거나 변경하지 못하도록 보호 기능이 필요하다.

#### 다중처리 시스템(Multi-Processing System)  
- 마이크로프로세서 여러 개를 연결해 다중 프로세서를 만들 수 있다. 이 방법은 초고속 프로세서를 사용하지 않고도 대형 컴퓨터의 능력을 얻을 수 있다.  
- 주/종 다중처리 시스템과 대칭적 구성 다중처리 시스템으로 구분된다.
- **두 개 이상의 CPU(프로세서)를 사용하여 여러 작업을 동시에 처리하는 시스템**이다. 여러 프로세서를 활용해 처리 능력과 시스템 성능을 높일 수 있다.
- **주종(Master-Slave) 다중처리 시스템**과 **대칭적(Symmetric) 다중처리 시스템**으로 구분된다.
	- **주종 다중처리 시스템**: 마스터 프로세서가 시스템을 제어하고, 슬레이브 프로세서가 주어진 작업을 수행한다.
	- **대칭적 다중처리 시스템(SMP)**: 각 프로세서가 동등한 지위를 가지며 운영체제와 시스템 자원을 공유하고 작업을 처리한다.

#### 분산처리 시스템(Distributed Processing System)  
- **여러 대의 컴퓨터가 각각 독립적인 운영체제와 메모리**를 가지고 **분산되어 동작**하며, **필요할 때** 통신망을 통해 서로 **통신하는 시스템**이다.
- 여러 개의 물리적 프로세서에 연산을 분산하여 자원 공유, 처리 속도 향상, 신뢰성 및 가용성 향상 등의 효과를 얻을 수 있다.

##### 운영체제의 구조
- **단일 구조 운영체제** 
	- 운영체제의 대부분의 기능을 하나의 커널에 포함하고, 동일한 커널 메모리 공간에서 실행하는 구조이다.
	- 시스템 호출을 통해 운영체제 서비스를 이용하며, 기능 간 직접적인 호출이 가능해 처리 속도가 빠르지만, 한 기능의 오류가 전체 시스템에 영향을 줄 수 있다.
	- 대표적인 예: 도스(DOS), 초기 유닉스(UNIX)

- **마이크로 커널 구조 운영체제**  
	- 커널에는 프로세스 관리, 메모리 관리, 프로세스 간 통신(IPC) 등 최소한의 기능만 포함하고, 파일 시스템이나 장치 드라이버 등의 나머지 기능은 사용자 공간의 서버로 실행하는 구조이다.
	- 커널의 크기가 작고, 기능 간 분리로 확장성과 유지보수성, 안정성이 높지만, 사용자 공간과 커널 공간 사이의 통신이 증가해 성능이 저하될 수 있다.

##### 운영체제의 처리 방식
1. **일괄처리(Batch Processing)**
	- 데이터를 일정량 또는 일정 기간 수집한 후 한꺼번에 처리하는 방식이다.
	- 처리 결과를 즉시 확인할 필요가 없는 작업에 적합하다.
	- 예: 급여 계산, 월별 요금 정산

2. **대화식 처리(Interactive Processing)**
	- 사용자와 시스템이 상호작용하며 입력에 대한 응답을 주고받는 처리 방식이다.
	- 사용자의 입력에 따라 시스템이 응답하므로 대화형 작업에 적합하다.
	- 예: 명령어 입력, 온라인 예약 시스템

3. **실시간 처리(Real-time Processing)**
	- 데이터가 발생하면 정해진 시간 내에 처리하고 결과를 반영하는 방식이다.
	- 처리 결과가 실제 작업이나 시스템 동작에 즉시 영향을 미쳐야 한다.
	- 예: 항공기 제어 시스템, 산업 공정 제어 시스템

##### 클라우드 컴퓨팅 기술  
- **IaaS**(Infrastructure as a Service)  
    - **서버, 스토리지, 네트워크** 등 IT **<mark>인프라</mark> 자원을 가상화**하여 인터넷으로 **제공하는 서비스**이다.
    - Amazon EC2(가상 서버), Amazon S3(클라우드 스토리지)

- **PaaS**(Platform as a Service)
	- 응용 프로그램의 **개발, 테스트, 배포 및 관리에 필요한** **<mark>플랫폼과 개발환경</mark>을 인터넷으로 제공하는 서비스**이다.
	- Google App Engine

- **SaaS(Software as a Service)**  
    - <mark><strong>완성된 소프트웨어</strong></mark> 를 인터넷을 통해 제공하며, 사용자는 별도의 설치나 관리 없이 웹 브라우저 등을 통해 필요한 소프트웨어를 이용하는 서비스이다.
	- 온디맨드(On-demand) 소프트웨어라고도 한다.
	- Google Workspace, Microsoft 365

#### 가상화(virtualization) 기술  
- **가상화** : **물리적 자원을 추상화하여 논리적 자원 형태로 표현하는 기술**
- 적용 대상에 따라 서버 가상화, 데스크톱 가상화, 스토리지 가상화, 네트워크 가상화, 소프트웨어 가상화로 구분된다.  
- 운영체제와 관련된 주요 가상화 기술은 **서버 가상화**이다.

#### 서버 가상화  
- **물리적 서버 하나에 가상 서버를 여러 개 구성**하는 방법이다.  
- 서버 하나에서 각 응용 프로그램과 운영체제를 독립된 환경으로 사용할 수 있어 **여러 운영체제가 한 시스템의 자원을 공유할 수 있다.** 

##### 베어메탈(bare-metal) 기반 가상화 : Type-1
![381](/assets/images/Pasted%20image%2020261022200750.png)
- **물리적 하드웨어에 하이퍼바이저를 직접 설치하여 호스트 운영체제 없이** 가상 CPU, 메모리, 디스크, 네트워크 카드 등을 갖춘 **여러 가상 머신(VM)을 생성하고 관리하는 방식**이다.
	- **하이퍼바이저(Hypervisor)**: **하나의 물리적 하드웨어에서 여러 가상 머신(VM)을 생성**하고, **각 가상 머신에** CPU, 메모리, 디스크 등의 **자원을 할당하고 관리하는 가상화 소프트웨어**
- 장점 : 향상된 성능을 제공하고 실시간 운영체제를 지원할 수 있다.  
- 단점 : 운영체제 위에서 구동되지 않으므로 디바이스용 드라이버, 하드웨어 플랫폼 드라이버 등을 포함해야 하고 설치와 구성이 어렵다. 

- **전가상화(Full Virtualization)**
![303](/assets/images/Pasted%20image%2020261022201337.png)
- 게스트 OS와 하드웨어 사이에서 하이퍼바이저가 명령 실행을 중재한다.
	- **Guest OS**: 가상 머신(VM) 내부에 설치되어 실행되는 운영체제이다. 하이퍼바이저가 제공하는 가상 하드웨어 자원을 사용한다.
- 하드웨어 에뮬레이션보다 일반적으로 빠르지만, 하이퍼바이저의 중재 과정에서 성능 저하가 발생할 수 있다.
- 일반적인 응용 프로그램 명령어는 하이퍼바이저의 개입 없이 직접 실행할 수 있다.
- 게스트 OS의 특권 명령어는 하이퍼바이저가 처리하며, 전통적인 전가상화 방식에서는 바이너리 변환(Binary Translation) 을 통해 처리하기도 한다.
	- 특권 명령어(Privileged Instruction) : 운영체제 커널처럼 특정 권한이 있는 상태에서만 실행할 수 있는 명령어
- 게스트 OS의 커널을 수정하지 않고 실행할 수 있다.
	- 게스트 OS는 자신이 가상화 환경에서 실행된다는 사실을 몰라도, 제공된 가상 CPU와 메모리 등의 하드웨어 환경을 사용해 동작할 수 있다.
	- 게스트 OS의 커널을 특별히 수정하지 않아도 하이퍼바이저가 특권 명령어 등을 적절히 처리한다.

- **반가상화(Para-Virtualization)**
![248](/assets/images/Pasted%20image%2020261022201248.png)
- 일반적인 명령어는 하드웨어에서 직접 실행하고, 특권 작업은 하이퍼콜(Hypercall) 을 통해 하이퍼바이저에 요청하므로 바이너리 변환이 필요하지 않다.
- 하이퍼바이저와 통신할 수 있도록 게스트 OS의 커널을 수정해야 한다.

##### 호스트 기반 가상화 : Type-2 
![354](/assets/images/Pasted%20image%2020261022200818.png)
 - 기존 운영체제 위에 가상화 프로그램을 설치하고, 그 프로그램을 통해 가상 머신을 실행하는 방식
- 장점 : 사용자가 호스트 OS를 수정하지 않고도 설치가 가능하다.  
- 단점 : 호스트 OS 위에서 가상 머신을 실행하므로, 하드웨어에서 직접 실행되는 베어메탈 기반 가상화 방식보다 성능이 떨어질 수 있다.

## 프로세스와 스레드
### 01 프로세스
#### 프로세스 정의
- 실행 중인 프로그램
- 실행 가능한 프로그램이 메모리에 적재되어 운영체제의 관리를 받으며 실행되는 상태로, 실행에 필요한 메모리 영역을 사용한다
- 프로세스는 반드시 한 개의 PCB(Process Control Block)와 연결된다
- 비동기적 행위를 일으키는 주체
- 디스패치가 가능한 대상
	- 디스패치(dispatch) : 운영체제가 준비 상태의 프로세스에 CPU를 할당하여 실행 상태로 전환하는 것.

#### 프로세스의 일반적인 메모리 구조
- 프로그램은 컴파일한 코드와 초기화 전역변수, 문자열과 문자열 상수 등 정적 데이터를 포함하는 정적 개체이다.
- 프로세스는 프로그램 카운터나 레지스터처럼 어떤 자원을 사용하는지 관련 정보가 들어있는 동적인 개체이다.
- 자원 할당의 단위
![303](/assets/images/memory_layout%201.png)
- **스택(stack)**
	- 데이터를 일시적으로 저장하는 영역
	- 지역변수, 매개변수 저장
	- 함수 호출 시 반환 주소 저장
	- 함수의 반환 값 저장에 사용될 수 있음
	- **문맥 교환** 및 인터럽트 처리 시 **CPU 레지스터 값 등을 임시 저장**하여 복원하는 데 활용됨
	- 함수를 호출할수록 커지고 반환하면 줄어든다.

- **힙(heap)**
	- 코드 영역과는 별도로 유지되는 자유영역
	- 동적으로 메모리를 할당하려고 프로그램 실행 중 시스템 호출을 사용했다가 해제하는 방법으로 활용
- **데이터(data)**
	- 프로그램 가상주소 공간
	- **전역변수나 정적변수를 저장**하거나 할당하고 실행하기 전에 초기화한다.
		- 변수 초기화: 프로그램 실행 시 전역변수나 정적변수에 초기값을 설정한다.
- **코드(code)**
	- 실행 명령을 포함하는 메모리거나 목적 파일에 있는 프로그램 영역
	- 프로그램을 시작할 때 프로세서가 디스크에서 읽어 실행하는 컴파일한 프로그램을 저장한다.

### 02 프로세스 종류
- 부모 프로세스
- 자식 프로세스 : 부모 프로세스에 의해 만들어지는 프로세스. 할 일이 끝나면 부모 프로세스에게 결과를 돌려주고 종료된다.
- 고아 프로세스 : 자식 프로세스가 아직 실행 중인데 부모 프로세스가 먼저 종료되어 버린 경우
- 좀비 프로세스 : 자식 프로세스가 실행을 종료했는데 프로세스 목록에 남아있는 경우

#### 1. 역할에 따른 분류
- 시스템(커널) 프로세스
	- 모든 시스템 메모리와 프로세스 명령에 엑서스할 수 있는 프로세스
	- 프로세스 실행 순서를 제어하거나 다른  사용자 및 커널(운영체제) 영역을 침범하지 못하게 감시하고, 사용자 프로세스를 생성하는 기능을 한다.
- 사용자 프로세스
	- 사용자 코드를 수행하는 프로세스
	- 사용자 응용프로그램을 수행하는 프로세스

#### 2. 병행 수행 방법에 따른 분류
- 독립 프로세스
	- 다른 프로세스에 영향을 주지 않거나 다른 프로세스의 영향을 받지 않으면서 수행하는 병행 프로세스
- 협력 프로세스
	- 다른 프로세스에 영향을 주거나 다른 프로세스에서 영향을 받는 병행 프로세스

### 03 프로세스 상태
#### 1. 프로세스 상태
  ![333](/assets/images/process_state_diagram.png)
1. 생성 : 프로세스의 작업 공간이 메인 메모리에 생성되고 운영체제 내부에 프로세스의 실행정보를 관리하기 위한 프로세스 제어 블록(PCB)이 만들어지는 상태  
2. 준비 : 프로세서에게 할당되기를 기다리는 상태  
3. 실행 : 프로세서를 점유하여 명령들이 실행되는 상태  
4. 대기 : 프로세스가 어떤 이벤트(입출력 종료와 같은 외부 신호)가 일어나기를 기다리는 상태  
5. 완료 : 프로세스의 수행이 끝난 상태  

#### 2. 프로세스 상태 변환  
- 준비 → 실행(dispatching)
	- 준비 상태의 프로세스는 디스패치(dispatcher)에 의해 프로세서가 부여되면 실행상태가 된다.  
- 실행 → **준비(time out)**
	- 어떤 프로세스가 프로세서를 계속 독점하는 것을 방지하기 위해 운영체제는 인터럽트 클록을 두어서 지정된 시간 동안만 프로세스가 프로세서를 점유하도록 한다.
	- 실행 상태에 있는 프로세스가 우선순위가 높은 프로세스에 의해 선점되었을때
- 실행 → <mark><strong>대기(block)</strong></mark>
	- 실행상태의 프로세스가 **지정된 시간 이전에 입출력 연산 등을 필요로 할 경우 그 프로세스는 스스로 프로세서를 양도**하게 된다.
- 대기 → 준비(wake up)
	- 입출력 작업이 끝났을 때, 대기 상태의 프로세스는 준비 상태로 변환한다.
	- 프로세스에 자신이 기다리고 있던 이벤트가 발생했다.

- 프로세스의 종료  
	- 프로세스가 마지막 명령을 실행하며 종료하며 운영체제에 프로세스의 삭제를 요청한다. 
	- 일괄처리 환경에서는 인터럽트를 발생하거나 시스템 호출로 중단 명령을 전달하여 프로세스를 종료한다.  
	- 대화형 환경에서는 사용자가 로그오프(log-off)하거나 터미널을 닫으면 프로세스를 종료한다.  
	- 이외 오류로 프로세스를 종료할 수 있다.

### 04 프로세스 제어 블럭(PCB, Process Control Block)
- 운영체제에 특정 프로세스에 대한 중요한 정보를 제공해 주는 데이터 블록이다.  
- 프로세스를 생성할 때 만들어지며 주기억장치에 유지되며 운영체제 내에서 한 프로세스의 존재를 정의한다. 프로세스의 실행이 종료되면 같이 삭제된다.  
- 인터럽트 처리, 자원할당, 스케줄링 등을 수행하는 운영체제의 모든 모듈에 의해 판독되고 수정될 수 있다.

#### PCB 구성요소
- **프로세스 식별자**(PID) : 각 프로세스의 고유 식별자
- 부모프로세스 식별자(PPID)
- **프로세스 상태** : 생성, 준비, 실행, 대기, 중단 등 상태 표시
- **프로그램 카운터** : 프로세스를 실행하는 다음 명령의 주소 표시
- **레지스터 저장 영역**
	- 누산기, 인덱스 레지스터, 스택 포인터, 범용 레지스터, 조건 코드 등의 정보
	- 컴퓨터 구조에 따라 수나 형태가 다르다.
	- 인터럽트가 발생하면 프로그램 카운터와 함께 저장한다.
- **프로세서 스케줄링 정보** : 프로세스의 우선순위, 스케줄링 큐의 포인터, 기타 스케줄 매개변수
- **계정 정보** : 프로세서 사용시간, 실제 사용시간, 사용 상한시간, 계정번호, 작업이나 프로세스 번호 등
- **입출력 상태 정보** : 특별한 입출력 요구 프로세스에 할당된 입출력장치, 열린 파일 리스트 등
- **메모리 관리 정보** : 운영체제가 사용하는 메모리 시스템에 따른 상한·하한 레지스터(경계 레지스터), 페이지 테이블이나 세그먼트 테이블 값

#### 프로세스 생성 시 필요한 세부 작업  
1. 새로운 프로세스에 <mark><strong>프로세스 식별자를 할당</strong></mark>.  
2. 새로운 프로세스를 위한 <mark><strong>주소 공간과 프로세스 제어 블록 공간을 할당</strong></mark>
3. <mark><strong>프로세스 제어 블록을 초기화</strong></mark> 한다. 프로세스 상태, 프로그램 카운터 등 초기화, 자원 요청, 프로세스 제어 정보(우선순위) 등을 포함한다
	- PCB 초기화: 프로세스 실행 및 관리를 위해 상태, 프로그램 카운터, 우선순위 등의 초기 정보를 설정하는 과정.
4. <mark><strong>해당 준비큐에 삽입</strong></mark>

### 05 <mark>문맥교환(Context Switching)</mark>

![context_switching 1.png](/assets/images/context_switching%201.png)
- 프로세서를 다른 프로세스로 전환하려면 **이전의 프로세스 상태 레지스터 내용을 보관하고, 다른 프로세스의 레지스터들을 적재하는 과정**을 말한다.
- 프로세스가 '준비 → 실행', '실행 → 준비', '실행 → 대기' 상태로 변환할 때 발생한다. 
- 문맥교환은 모두 **과부하(overhead)가 발생**한다.  
- 운영체제에서 문맥교환은 자주 발생하므로 가능한 효율적으로 구현되어야 하는데 이를 위해 **스레드**(thread)를 사용한다.

### 06 스레드(Thread)
#### 1. 스레드의  개념
- **프로세스는 자원과 제어로** 특성을 **구분**할 수 있는데 이 중 <mark><strong>제어만 분리한 실행 단위를 스레드</strong></mark>(thread)라 한다.
- 프로세스 하나는 스레드 한 개 이상으로 나눌 수 있다.  
- <mark><strong>CPU 스케줄링의 단위</strong></mark>
- 스레드들은 프로세스의 직접 실행 정보를 제외한 나머지 프로세스 관리 정보를 공유한다.  
	- **프로그램 카운터(PC)와 스택 포인터(SP) 등을 비롯한 스레드 실행 환경 정보(문맥 정보), 지역 데이터, 스택을 독립적으로 갖는다.**  
	- <mark><strong>코드, 전역 데이터, 힙을 다른 스레드와 공유</strong></mark>![Pasted image 20261023153709.png](/assets/images/Pasted%20image%2020261023153709.png)
- **응용 프로그램에는 하나 이상의 프로세스**가 있고, **프로세스에는 한 개 이상의 스레드**가 있다.  
- **같은 프로세스의 스레드들은 동일한 주소 공간(코드,데이터,힙)을 공유**한다.
- **스레드도 프로세스처럼 준비, 실행, 대기, 종료 상태가 있다.**
- **멀티프로세서 환경에서는 각각의 스레드가 다른 프로세서에서 수행될 수 있다.**
- 다중 스레드는 한 스레드에 문제가 생기면 프로세스 전체 실행에 문제를 준다.
- 한 프로세스 내의 **스레드들은 서로 공유하는 메모리 영역으로 통신**
- 다른 프로세스에 속한 스레드 간의 교착상태 발생 가능
- 프로세스가 스와핑되면 해당 프로세스에 속한 모든 쓰레드 역시 스와핑된다.
- 쓰레드를 지원하기 위해서 운영체제의 지원은 필수적이지 않다.
- Pthread : 스레드 생성과 동기화를 위해 POSIX가 제정한 표준 API

#### 2. 스레드의 이점
- **프로세스의 자원과 메모리 공유 가능** : 스레드들이 프로세스 자원 하나와 메모리를 공유하므로 응용 프로그램 하나가 동일한 주소 공간에서 스레드를 여러 개 실행하여 시스템 성능을 향상시킬 수 있다.  
- **오버헤드 감소** : 프로세스를 생성하는 것보다 스레드를 생성하여 문맥 교환을 수행하면 오버헤드가 줄어든다.  
- **다중처리(멀티 프로세싱)로 성능과 효율 향상** : 각 스레드를 여러 프로세서에서 병렬로 실행하여 성능과 효율성을 높일 수 있다.
- 프로세스 내 쓰레드 간 통신은 커널 개입을 필요로 하지 않기 때문에 프로세스 간 통신보다 더 효율적으로 이루어진다.

#### 3. 단일 스레드와 다중 스레드

![thread_diagram_ko 3.png](/assets/images/thread_diagram_ko%203.png)
  
- 프로세스의 모든 스레드들은 그 프로세스의 자원과 상태를 공유하게 되고 또한 같은 주소 공간에 존재하며 동일한 데이터에 접근한다.

##### 단일 스레드  
프로세스 하나에 스레드 한 개를 실행하는 전통적인 방법으로 아직 스레드 용어가 탄생하기 전이라 개념이 불확실하다. 도스가 대표적인 예이다.  
##### 다중 스레드  
- 동일 프로세스의 스레드는 자원을 공유하므로 자원 생성과 관리의 중복성을 최소화하여 실행 능력을 향상시킬 수 있다.  
- **각 스레드는 커널이 개입하지 않고도 독립적으로 실행할 수 있어** 서버에서 많은 요청을 효과적으로 처리할 수 있다.
- 프로세스보다 **스레드를 생성하는 것이 더 빠르고**, **동일한 프로세스에 있는 스레드 간의 교환이나 종료도 더 빠르다.**  
- **프로그램을 변경하지 않고 스레드를 병렬로 처리**하여 효율을 극대화할 수 있다.  
- 스레드별 실행 환경 정보는 독립적으로 유지하지만, 코드·데이터·힙 영역을 공유하므로 프로세스 간 문맥 교환보다 **동일 프로세스 내 스레드 간 문맥 교환의 오버헤드가 작다.**

## 병행 프로세스
### 01 병행 프로세스
- **프로세서(CPU) 하나는 한 번에 프로세스 하나만 실행할 수 있다.**  
	- **프로세서(Processor)** : 프로그램 명령어를 해석하고 실행하는 하드웨어 장치(**=CPU**)
- **병행 프로세스** : **운영체제가 프로세서를 빠르게 전환하여 마치 프로세스 여러 개를 동시에 실행하는 것처럼 보이게 하는 것**
#### 병행 프로세스의 동기화 및 상호 배제를 위한 조건
- **공유 자원을 배타적으로 사용**
- 병행 프로세스들 사이에는 **동기화**가 이루어져야 한다.  
- 두 프로세스 사이에는 데이터 교환을 위한 **통신**이 이루어져야 한다.  
- 프로세스들은 동시에 수행되는 **다른 프로세스들의 실행 속도와 관계없이 항상 일정한 실행 결과가 보장**하도록 결정성을 확보해야 한다.  
	- 결정성(Determinism): 같은 조건에서 실행했을 때 결과가 일정하게 결정되는 성질.
- **교착상태를 해결**해야 하며 **병행 프로세스들의 병렬 처리 능력을 극대화**한다.
- 병행 **프로세스를 수행하는 과정에서의 상호배제를 보장**한다.
	-  상호배제 : 어떤 프로세스가 작업을 실행 중일 때 나머지 프로세스는 그것과 관련된 작업을 수행할 수 없도록 하는 것.

### 02 상호 배제와 동기화
#### 1. 임계영역(Critical Section)
- **임계자원**: **여러 프로세스가 공유**하며, **동시에 접근할 경우 문제**가 발생할 수 있는 자원.
- **임계영역**: **공유 자원에 접근하는 코드 영역**으로, **상호 배제가 필요**한 부분.
- 프로세스가 공유 데이터를 액세스하는 동안 그 프로세스는 임계영역 내에 있다고 한다. 
- 임계영역에는 한 순간 반드시 단 하나의 프로그램만이 허용된다.  
- 임계영역 내 작업은 가능한 한 신속하게 수행
	- 임계영역의 실행 시간이 길어지면 다른 프로세스들이 자원을 사용하지 못하고 대기하는 시간이 길어지기 때문
- 프로세스는 임계영역 내에서 대기(block)되어서는 안 되며 무한루프에 빠지지 않아야 한다

##### 임계영역 문제를 해결하기 위한 조건  
-  **상호배제** : 프로세스 P가 임계영역을 수행 중일 때 다른 어떤 프로세스도 임계영역을 수행할 수 없다.  
- **진행** : 임계영역을 실행 중인 프로세스가 없고 여러 프로세스가 진입을 원할 때, 잔류영역에 있지 않은 프로세스 중 하나를 선택하며 선택이 무한정 지연되어서는 안 된다.
	- 잔류영역(Remainder Section): 프로세스가 임계영역에서 작업을 마친 후, 다음 임계영역에 진입하기 전까지 수행하는 나머지 코드 영역.
- **제한된 대기** : 한 프로세스가 임계영역 진입을 요청한 후 허용되기까지, 다른 프로세스들이 임계영역에 진입할 수 있는 횟수에는 제한이 있어야 한다. 특정 프로세스가 임계영역에 무한정 들어가지 못하는 상황을 방지하기 위해.

##### 상호배제 방법  -> 정리
1. **데커의 알고리즘**(Dekker's algorithm) : 두 프로세스가 서로 통신하기 위해 **공유메모리**를 사용하여 충돌 없이 단일 자원을 공유할 수 있도록 허용한다.  
2. **TestAndSet 명령어** : 기계를 비교하거나 단어 내용을 검사, 수정하는 특별한 하드웨어 명령어(TestAndSet)를 사용한다.  
3. **세마포어**(Semaphore) : 세마포어 변수 값이 true일 때 프로세스 상태를 확인하는 동기화 도구이다.  
4. **모니터**(Monitor) : 공유 데이터에 여러 프로세스가 동시에 접근하지 못하도록 관리하는 동기화 기법
	- 세마포어와 비슷한 역할을 하지만 제어가 쉽다.  
	- 모니터 안에서 정의된 프로시저는 모니터 안에서 지역적으로 정의된 변수들과 형식적인 매개변수들만 접근할 수 있다.  
	- 모니터의 지역 변수들은 지역 프로시저에 의해서만 접근된다.
	- 모니터 구조는 한 순간에 하나의 프로세스만 모니터 안에서 활동하도록 보장한다.

##### 모니터(monitor)
![Pasted image 20261022202349.png](/assets/images/Pasted%20image%2020261022202349.png)
**모니터의 구조**  
- 공유 데이터, 임계영역이 포함된 프로시저, 초기화 코드로 구성된 모듈이다. 데이터 정의와 프로시저의 독점적 제어를 제공한다.
- 초기화 코드는 모니터 생성 시 실행되며, 공유 데이터는 모니터 내부의 프로시저로만 접근할 수 있다.
	- **프로시저: 프로그램 안에서 특정 작업을 수행하는 코드**
- 프로세스는 모니터의 프로시저를 호출하여 모니터에 진입한 후 공유 데이터에 접근한다.
- 한 번에 하나의 프로세스만 모니터에 진입할 수 있도록 제한하여 상호배제를 실현한다.

#### 2. 프로세스 동기화의 대기 방식 -> 다시 정리
##### BusyWaiting(=바쁜 대기, 능동 대기)
- 조건이 충족될 때까지 반복적으로 확인하면서 대기.
- 임계 영역에 들어갈 수 있을 때까지 아무 작업도 하지 않고 임계 영역에 접근이 가능한지 무한으로 검사
- 계속 CPU를 사용

##### Blocking(=수면 대기)
- 조건이 충족될 때까지 대기 상태로 전환
- 대기 중에는 CPU를 사용하지 않음

##### 스핀락(Spinlock)
- 잠금을 획득할 때까지 반복적으로 확인하는 동기화 기법. 비지 웨이트 방식으로 대기함.

##### 슬립(Sleep)
- 일정 시간 또는 조건이 충족될 때까지 실행을 중단하고 대기함.

#### 3. 세마포어(Semaphore)![Pasted image 20261021160549.png](/assets/images/Pasted%20image%2020261021160549.png)
- 여러 프로세스나 스레드가 **공유 자원에 접근하는 순서를 제어**하고, **동기화를 수행하기 위해 사용**하는 정수형 변수.
- S = 1 이면 임계영역 실행 중인 프로세스 없음
- S = 0 이면 임계영역 실행 중인 프로세스 존재
- 잘못 사용하면 교착상태나 기아 현상이 발생할 수 있다
##### 기본 동작
``` 
P(S):
	while S <= 0 do no-op;
	S = S - 1
V(S):
	S = S + 1	
```
- **P 연산(wait)** : 자원을 사용하기 위해 세마포어 값을 감소시키고, 자원이 없으면 대기 (자원 획득)
- **V 연산(signal)** : 자원 사용이 끝났음을 알리고 세마포어 값을 증가시키거나 대기 중인 프로세스를 깨움 (자원 반환 , 대기 프로세스의 실행 허용)
	- P와 V 연산은 **원자적으로 수행**되어야 한다
		- 원자적 수행(Atomic Operation): 하나의 연산이 중간에 중단되거나 다른 프로세스에 의해 간섭받지 않고, 하나의 작업 단위로 완전히 수행되는 것.
##### 세마포어 종류
- **이진 세마포어**(Binary Semaphore): 값이 0 또는 1이며, **상호 배제 및 프로세스 동기화**에 사용된다.
- **계수 세마포어**(Counting Semaphore): 여러 개의 동일한 자원에 대한 사용 가능 개수를 관리한다.

## 교착 상태
- 둘 이상의 프로세스가 서로 상대방이 점유한 자원을 기다리며 무한정 대기하여, 어느 것도 더 이상 진행하지 못하는 상태

### 자원 할당 그래프
![Pasted image 20261022204453.png](/assets/images/Pasted%20image%2020261022204453.png)
- 자원할당 그래프에서 사이클이 존재 -> 프로세스와 자원이 교착 상태

### <mark>교착 상태 필요 조건</mark>
- <mark><strong>상호배제</strong></mark> : **한 번에 한 프로세스만이 그 자원을 사용**할 수 있다.
- <mark><strong>점유와 대기</strong></mark> : 적어도 하나의 자원을 가진 프로세스가 다른 프로세스의 자원을 얻기 위해 대기
- <mark><strong>비선점</strong></mark>
- <mark><strong>순환대기(환형대기)</strong></mark>

### 교착 상태 처리 기법
#### 교착상태 예방
- 상호배제 조건을 제외한 세 가지 필요조건 중 하나 이상을 부정하여 교착상태의 발생을 방지한다.

##### 점유와 대기조건 부정
- 각 프로세스는 필요한 모든 자원을 한 번에 요구하며, 자원이 모두 할당되지 않으면 자원을 점유하지 않고 대기한다.

##### 비선점 조건 부정
- 자원을 점유한 프로세스가 추가 자원을 할당받지 못하면, 기존에 점유한 자원을 반납하고 필요할 때 해당 자원이나 다른 자원을 다시 요구해야 한다

##### 순환 대기 조건 부정
- 모든 프로세스에 각 자원 유형별로 할당 순서를 부여한 후 순서에 따라 자원을 요구할 수 있도록 한다.

#### 교착상태 회피
##### **은행가 알고리즘**
- 작업에 필요한 자원 수에 따라 프로세스 수행에 필요한 자원이 충분한지 검사하는 **교착상태 회피 알고리즘**
- 프로세스가 자원을 요청하면, 해당 자원을 할당한 후에도 안전 상태를 유지할 수 있는 경우에만 자원을 할당한다.
- **안전 상태**(Safe State): 모든 프로세스가 최대 요구량까지 자원을 받고 끝낼 수 있는 실행 순서(안전 순서)가 **하나라도 존재**하는 상태
- **불안전 상태**(Unsafe State)
	- 그런 안전 순서가 **존재하지 않는** 상태
	- **교착 상태는 불안정 상태이지만, 모든 불안정 상태가 교착 상태인 것은 아님.**

**안정 상태 예시**
3개의 프로세스, 총자원이 12개, 현재 할당량은 10개, 잔여량은 2개

| 프로세스 | 현재할당량 | 최대요구량 | 추가요구량 |
| ---- | ----- | ----- | ----- |
| A    | 2     | 9     | 7     |
| B    | 4     | 6     | 2     |
| C    | 4     | 8     | 4     |
프로세스 B → 프로세스 C → 프로세스 A 순으로 자원을 할당하면 모든 프로세스의 수행을 마칠 수 있다.

**불안정 상태 예시**
3개의 프로세스, 총자원이 12개, 현재 할당량은 11개, 잔여량은 1개  

|프로세스|현재할당량|최대요구량|추가요구량|
|---|---|---|---|
|A|6|9|3|
|B|3|9|6|
|C|2|4|2|
남은 자원 1개로 할당받아 완료될 수 있는 프로세스가 존재하지 않는다.

#### 교착상태 탐지
- 교착상태 예방 알고리즘을 사용하지 않으면, 교착상태가 발생할 수 있다
- 교착상태 발생 여부를 확인하기 위해 교착상태 탐지 알고리즘을 수행한다.
- 교착상태 탐지 알고리즘의 수행 시기를 결정하기 어렵다.
- 교착상태 탐지 알고리즘을 자주 실행하면 시스템 성능이 저하된다.

#### 교착상태 회복
##### 프로세스 중지
- 교착상태 프로세스들을 모두 중지한다
- 교착상태가 해결될 때까지 한 프로세스씩 중지한다.
- 종료할 프로세스를 우선순위에 따라 선택한다

##### 자원선점
- **희생자의 선택** : 비용을 최소화하도록 자원을 회수할 프로세스 선택
- **복귀** : 자원을 선점당한 프로세스를 이전의 안전한 상태로 되돌린 후 재시작한다.
- **기아** : 동일한 프로세스가 반복적으로 희생자로 선택되어 작업이 지연되는 현상

## 스케줄링
- 프로세스가 생성되어 실행될 때 필요한 시스템의 여러 자원을 해당 프로세스에게 할당하는 작업
- 반환(응답) 시간 : 프로세스의 대기시간과 실행시간의 합

##### 우선순위 스케줄링
- 프로세스의 우선순위가 높은 것을 우선적으로 CPU에게 할당하는 스케줄링
- 선점 또는 비선점으로 수행 가능
- 기아 현상이 발생할 수 있음
- 실시간 시스템에 사용 가능

### 비선점 스케줄링
- 실행 중인 프로세스가 종료되거나 대기 상태가 될 때까지 **CPU를 강제로 빼앗지 않음.**
- 문맥 교환이 적어 오버헤드가 적지만, 짧은 작업도 오래 기다릴 수 있음.
- 일괄 처리 방식에 적합
- **FCFS, SJF, HRN**

#### FCFS(First Come First Service, 선입 선출) = FIFO
- 준비상태 큐에 도착한 순서에 따라 차례로 CPU를 할당하는 기법
- 준비 큐에서 가장 오래 대기한 프로세스를 다음 실행 프로세스로 선정

#### <mark>SJF(Shortest Job First)</mark>
- **준비상태 큐에서** 기다리고 있는 프로세스들 중에서 **실행 시간이 가장 짧은 프로세스**에게 **먼저 CPU를 할당**하는 기법.
- <mark><strong>가장 적은 평균 대기 시간</strong></mark> 을 제공하는 최적 알고리즘.

#### HRN(Highest Response-ratio Next)
- **대기 시간과 서비스(실행) 시간을 이용**하는 기법
- 우선 순위를 계산하여 그 숫자가 가장 높은 것부터 낮은 순으로 우선순위가 부여.
- $우선순위 계산식 = (대기시간 + 서비스 시간)/서비스 시간$
- 선점 SJF 스케줄링의 기아상태를 해결하기 위해 사용.

### 선점 스케줄링
- 실행 중인 프로세스의 **CPU를 강제로 빼앗아 우선 순위가 높은 다른 프로세스에 할당할 수 있다.**
- 응답 시간이 빠르지만, 문맥 교환이 잦아 오버헤드가 발생할 수 있음
- 대화형 시스템에서 유용
- **RR, SRT**, 다단계 큐 알고리즘(MLQ), 다단계 피드백 큐 알고리즘(MFQ)
#### <mark>RR(Round Robin)</mark>
- **준비 상태 큐의 프로세스**들을 **시간 할당량**(Time Slice, Quantum) **동안만 실행**하고, 실행이 완료되지 않으면 큐의 뒤로 보내 다음 프로세스에게 CPU를 할당하는 기법.
- 시분할 시스템을 위해 고안.
- 할당되는 시간이 클 경우 FCFS 기법과 같아지고, 할당되는 시간이 작을 경우 문맥 교환 및 오버헤드가 자주 발생되어 요청된 작업을 신속히 처리할 수 없음.
#### <mark>SRT(Shortest Remaining Time)</mark>
- **현재 실행 중인 프로세스의 남은 시간**과 **준비상태 큐에 새로 도착한 프로세스의 실행 시간을 비교**하여 **가장 짧은 실행 시간을 요구하는 프로세스에게 CPU를 할당**하는 기법.
- 시분할 시스템.

#### 다단계 큐 알고리즘(MLQ)
![multilevel_queue_scheduling.png](/assets/images/multilevel_queue_scheduling.png)
- 프로세스의 종류나 특성에 따라 여러 개의 준비 큐로 나누고, **각 큐에 서로 다른 스케줄링 알고리즘을 적용**하는 방식.
- 일반적인 다단계 큐에서는 **프로세스가 한 큐에 고정되어 다른 큐로 이동하지 않는다**.

#### 다단계 피드백 큐 알고리즘(MFQ)
![Pasted image 20261022234837.png](/assets/images/Pasted%20image%2020261022234837.png)
- 프로세스의 실행 특성에 따라 큐 사이를 이동시켜 우선순위를 조정하는 스케줄링 방식
- 여러 개의 큐를 구성하고 프로세스의 실행 특성에 따라 큐 사이의 이동을 허용한다.
- CPU 사용 시간이나 대기 시간 등에 따라 프로세스의 우선순위를 조정할 수 있다.
- **입출력 위주의 프로세스와 CPU 위주의 프로세스로 구분하여 특성에 따라 서로 다른 CPU 이용시간을 할당.**
- 우선순위가 높은 큐에는 짧은 시간 할당량을, 낮은 큐에는 긴 시간 할당량을 부여할 수 있다.
- 프로세스의 우선순위를 높이는 방식으로 기아 현상을 완화할 수 있다

### 메모리 관리 기법

##### 중첩(Overlay) 기법
![Pasted image 20261023192407.png](/assets/images/Pasted%20image%2020261023192407.png)
- 프로그램을 여러 부분으로 나누어 현재 실행에 필요한 부분만 메모리에 적재하는 기법.
- 프로세스의 모든 논리 주소 공간은 그 프로세스가 수행되기 전에 실제 메모리에 적재되어야 하므로, 프로세스의 크기는 실제 메모리의 크기로 제한된다.  
- 한 프로세스에 할당된 메모리보다 큰 프로그램은 중첩 기법을 사용하여 해결한다.

##### 스와핑(Swapping) 기법
![385](/assets/images/Pasted%20image%2020261023185152.png)
- 사용자 기억장치의 현재 내용이 보조기억장치에 기억되고, 다음 사용자의 내용이 기억장치에 읽혀오는 것을 Swap이라 한다.  
- 실행이 끝난 프로세스를 보조기억장치로 보내고 다른 프로세스를 주기억장치의 가용공간으로 불러와 실행한다.

##### 절대 적재
![Pasted image 20261023190932.png](/assets/images/Pasted%20image%2020261023190932.png)
- 주기억장치가 여러 개의 고정된 분할로 나누어져 있고 하나의 작업은 절대 컴파일러에 의해 번역되어 지정된 분할에서 실행된다.  
- 한 작업이 실행 준비가 되어있어도 지정된 자신의 분할이 이미 차 있다면, 다른 분할이 이용가능하더라도 기다려야 한다

##### 재배치 적재
![Pasted image 20261023190941.png](/assets/images/Pasted%20image%2020261023190941.png)
- 모든 작업을 하나의 큐에 넣어서, 어느 분할에서든지 실행 가능하도록 한 기법이다.  
- 절대 적재기법보다 주기억장치의 낭비를 줄이지만 운영체제의 부담은 커진다.

#### 고정분할 기억장치 할당
- 다중 프로그래밍을 지원하기 위한 간단한 방법은 메모리를 여러 개의 **고정된 크기로 분할**(정적분할)하는 것이다.  
- 각 분할은 하나의 프로세스를 포함했고 각각의 크기로 분할된 작업 큐에는 해당 크기 내의 작업들이 지정된 분할에서만 실행될 수 있다.
##### 기억장치 단편화
- **외부 단편화** : 대기 중인 작업에게는 분할이 너무 적어 분할 전체가 빈 공간으로 있을 때의 상태
- **내부 단편화** : 하나의 분할에 작업을 할당하고 남은 빈 공간
 ![Pasted image 20261023184444.png](/assets/images/Pasted%20image%2020261023184444.png)


#### 가변 분할 기억장치 할당
![Pasted image 20261023184336.png](/assets/images/Pasted%20image%2020261023184336.png)
- **가장 합리적인 분할의 크기를 결정하여 각 작업에게 주기억장치를 할당하는 기법**으로, 고정된 분할의 경계를 없애고 **각 작업에 필요한 만큼의 기억장치를 할당**한다.  
- 가변 분할 할당은 **내부 단편화는 절대 발생하지 않는다.**  
- 가변 분할 할당은 **외부 단편화 문제가 발생**한다.  
- 프로세스들이 메모리에서 제거되고 새로운 프로세스가 적재될 때 사용가능 기억공간에 일부 적재되고 나머지 공간은 작은 조각으로 나누어진다.  
- **쓰레기수집(Garbage Collection)** : 작은 단편화 공간을 모아서 하나의 큰 가용 공간을 만드는 것

##### 통합(Coalesing)
![Pasted image 20261023192706.png](/assets/images/Pasted%20image%2020261023192706.png)
- 하나의 작업이 끝났을 때 그 기억장소가 비어있는 다른 기억장소와 인접되어 있는지를 검사하여 하나의 공백으로 합하는 과정이다.

##### 압축(Compaction)
![Pasted image 20261023192942.png](/assets/images/Pasted%20image%2020261023192942.png)
- 메모리 내용들을 적절히 움직여서 모든 사용가능 메모리를 하나의 큰 가용공간으로 만든다.  
- 압축하는 동안 시스템은 모든 일을 멈추어야 한다.  
- 메모리 테이블을 관리하고 유지해야 하므로 오버헤드가 발생한다.

## 가상 메모리
### 01 가상메모리의 개념
#### 1. 가상 메모리
- 프로그래머나 사용자들이 디스크의 커다란 메모리 공간을 가상메모리로 인식하고 이를 이용하여 메모리의 부족함 없이 다중 프로그래밍 환경을 실현하는 기법이다.  
- 사용자와 논리적 주소를 물리적으로 분리하여 사용자가 주기억장치 용량을 초과한 프로세스에 주소를 지정해서 주기억장치를 제한 없이 사용할 수 있도록 한다.  
- 프로그램 전체를 동시에 실행하지 않으므로 요구한 메모리 전체가 아닌 일부만 적재해도 실행이 가능하다.
- 중첩을 고려하여 프로그래밍할 필요가 없으므로 프로그래밍이 쉽다.
- **프로세서의 이용률과 처리율을 향상시킬 수 있다.**
- <mark><strong>응답시간이나 반환시간은 향상되지 않는다.</strong></mark>

#### 2. 동적 주소 반환(DAT : Dynamic Address Translation) 기법
- 가상 메모리를 이용하여 메모리 공간 문제를 해결하기 위해서는 실행 중인 프로세스가 참조하는 주소와 주기억장치에서 사용하는 물리적 주소를 분리해야 한다.  
- 매핑(mapping) :  가상주소(논리적 주소, 프로그램 주소)를 물리적 주소로 변환하는 과정
- 동적 주소 변환(DAT, Dynamic Address Translation)은 인위적 연속성을 제공한다.
- **인위적 연속성** : 가상 주소에서 연속적이라고 주기억장치에서도 연속적일 필요가 없다는 의미
- 동적 주소 변환기법은 가상메모리의 어느 부분이 현재 실제 메모리 어디에 위치하는가를 나타내는 대응표(mapping table)를 유지해야 한다.

#### 3. 블록(가상메모리의 이동단위) 사상
- 가상메모리의 블록을 주기억장치 블록에 대응시키는 기법
- **고정 길이 블록 : 페이지(Page) -> 페이징(Paging)**
- **가변 길이 블록 : 세그먼트(Segment) -> 세그테이션(Segmentation)**

##### 페이징(Paging)
![376](/assets/images/Pasted%20image%2020261023193712.png)
-  **프로세스의 논리 주소 공간을 고정 크기의 페이지(Page) 로 나누고, 주기억장치를 고정 크기의 프레임(Frame) 으로 나누어 관리하는 메모리 관리 기법.**
- **페이지와 프레임의 크기는 동일**
- 페이지 테이블을 이용하여 페이지 번호와 프레임 번호를 매핑한다.
- <mark><strong>외부 단편화가 발생하지 않지만, 내부 단편화가 발생할 수 있다</strong></mark>.
- 페이지 크기를 작게 설계함으로써 내부 단편화를 줄일 수 있다.
- 페이지 사상으로 비용이 증가하고 수행속도가 감소한다.
- 페이지는 프로그램에 상응하는 논리적 의미를 갖지 못한다.
![446](/assets/images/Pasted%20image%2020261023195205.png)
- **페이징 시스템의 하드웨어 구조와 원리**
	- **논리적 주소**는 **페이지 번호와 변위(offset)로 구성**
	- **페이지 번호 p를 이용하여 페이지 테이블의 p위치에 저장된 f값을 얻는다.**
	- **f는 메모리의 페이지 기준 주소**로, **메인 메모리의 프레임 번호**이다.
	- **기준 주소 f에 변위를 더하면 메인 메모리의 물리적 주소**가 된다
	- **페이지 테이블(페이지 매핑 테이블)을 이용**하여 **논리적 주소를 물리적 주소로 변환**한다.
	- 페이지 테이블은 페이지의 논리적 주소인 **페이지 번호**와 이에 대응하는 물리적 주소인 페이지 **프레임 주소**를 포함한다.
	- **페이지 테이블은 별도의 레지스터로 구성하거나 메인 메모리에 배치하기도 한다.**

- **페이지 공유와 보호**  
	- 페이징 시스템은 **시분할 환경에서 중요한 공통 코드를 공유할 수 있다.**
	- 페이징 시스템에서는 프로세스를 메모리에 연속적으로 할당할 필요가 없기 때문에 **여러 프로세스가 메모리를 공유할 수 있다.** **이 공유 코드는 재진입 코드 또는 순수 코드라고도 하며, 오직 읽을 수만 있으며 스스로 수정하지는 못한다**.
	- **페이지 테이블에 보호 비트를 추가하여 페이지 보호를 할 수 있다.**

- **블록을 작게 설계하면**  
	- 관리할 블록의 개수가 많아진다.  
	- 블록사상표의 크기가 커진다.  
	- 페이지 fault, 교체가 자주 일어난다.  
	- CPU 유휴시간이 길어진다.  
	- 1개의 블록이동시간은 짧다.  
	- 디스크로부터 블록이동이 자주 발생한다.  
	- 필요한 부분만 가져올 수 있다.  
- **블록을 크게 설계하면**
	- 관리할 블록의 개수가 적어진다.
	- 블록사상표의 크기가 작아진다.
	- 페이지 fault, 교체가 덜 일어난다.
	- CPU 유휴시간이 덜 발생한다.
	- 1개의 블록이동시간은 길다.
	- 디스크로부터 블록이동이 덜 발생한다
	- 필요치 않은 부분도 함께 온다.

- **역방향 페이지 테이블 (IPT, Inverted Page Table)**  
	- 페이지 테이블에서 물리 페이지 번호를 포함한 엔트리만 유용하기 때문에 가상 페이지 번호 대신에 물리 페이지 번호를 기준으로 주소 변환 테이블을 생성한다.  
	- 이와 같은 주소 변환 테이블을 이용하는 것을 역방향 페이지 테이블 방식이라 한다.
	- 역방향 페이지 테이블 방식의 경우, 주소 변환을 위한 테이블의 크기가 가상 주소 공간의 크기와 무관하고 메모리의 크기에 달렸다.
	- 가상 주소에서 추출한 가상 페이지 번호를 역방향 페이지 테이블의 모든 엔트리와 비교해야 하므로 많은 시간이 걸린다.
	- 이런 문제점을 줄이기 위해 해시 함수(hash function)를 사용한다.  

- **변환 색인 버퍼 (TLB, Translation Lookaside Buffer)**
	- 페이지 테이블 중 **최근에 참조된 주소 변환 정보를 캐시 메모리에 저장함으로써 주소 변환을 위한 메모리 접근을 줄이기 위해 사용**한다.
### 세그멘테이션(Segmentation)
- 프로세스의 논리 주소 공간을 **크기가 서로 다른 논리적 단위인 세그먼트로 나누어 관리하는 메모리 관리 기법.**
- 세그먼트는 코드, 데이터, 스택 등 프로그램의 논리적 구성 단위로 나눌 수 있다.
- 세그먼트 테이블을 이용하여 세그먼트의 시작 주소와 길이 등을 관리한다.
- <mark><strong>내부 단편화는 발생하지 않지만, 외부 단편화가 발생할 수 있다.</strong></mark>
- 세그먼트 공유와 보호 측면에서 세그먼트는 페이지보다 수행방법이 쉽고 명확하다.
![Pasted image 20261023203334.png](/assets/images/Pasted%20image%2020261023203334.png)

3200 + 250 -> 3450번지로 매핑
- **세그먼테이션 개요**  
	- 세그먼테이션은 프로세스 관점을 지원하여 메모리를 크기가 서로 다른 세그먼트로 나누고, 프로그램을 구성하는 서브루틴, 프로시저, 함수나 모듈 등으로 세그먼트를 구성한다.
	- 각 세그먼트는 연관된 기능을 수행하는 하나의 모듈 프로그램으로 생각하며, 메모리의 연속된 위치에서 구성하되 서로 인접할 필요는 없다.  
	- 프로세스에 따라 세그먼트의 크기가 다르므로 메모리를 크기가 일정한 페이지 프레임으로 나누지 않고 동적 분할 방법으로 할당한다.
- **세그먼트 공유**
	- 페이징 시스템은 페이지 테이블의 공유 항목을 표시해야 하지만, **세그먼트는 공유한다고 선언만 하면 된다.**
	- **2개 이상인 다른 프로세스의 세그먼트 테이블에 있는 항목은 동일한 메모리 주소를 지정하면 공유할 수 있다.**


### <mark>페이지 교체 알고리즘</mark>
##### 최적 페이지 교체(OPT)
- 모든 교체 알고리즘 중 페이지 부재 비율이 가장 낮다
- 앞으로 가장 오랫동안 사용하지 않을 페이지를 교체 대상으로 선택한다. 
- 현실적으로 구현하기 어렵다.

#### FIFO(First In First Out)
- 가장 먼저 들어와서 가장 오래 있었던 페이지를 교체

#### <mark>LRU(Least Recent Used)</mark> -> 정리
- 최근에 **가장 오랫동안 사용하지 않은 페이지를 교체**
+) 스택을 이용한 LRU 알고리즘

#### <mark>LFU(Least Frequently Used)</mark>
- **사용 빈도가 가장 적은 페이지를 교체**

#### NUR(Not Used Recently)
- **최근 참조 여부와 페이지 수정 여부를 기준으로 교체**.
- 참조 비트(R): 페이지가 최근에 참조되었는지 나타냄.
    - 0 : 최근 참조되지 않음 
    - 1 : 최근 참조됨
- 변형 비트(M): 페이지의 내용이 수정되었는지 나타냄.
    - 0 : 수정되지 않음
    - 1 : 수정됨
- 참조 비트와 변형 비트의 조합으로 페이지를 4개 그룹으로 분류하고, 우선순위가 가장 높은 그룹에서 교체할 페이지를 선택한다.

### 적재정책 -> 정리
#### 지역성(Locality)
- 실행 중인 프로세스에 의해 나타나는 특성으로 프로세스들은 기억장치 내의 정보를 균일하게 액세스하는 것이 아니라 어느 한 순간에 특정부분을 집중적으로 참조한다.  
- 지역성은 캐시 메모리, 연관 기억장치의 성립 이유가 되고 Working Set를 뒷받침한다.  
- 시간지역성은 처음에 참조된 기억장소가 가까운 미래에도 계속 참조될 가능성이 높다는 것을 의미한다. (Looping, Subroutine, Stack, Counting과 Totaling에 사용되는 변수)  
- 공간지역성은 일단 하나의 기억장소가 참조되면 그 근처의 기억장소가 계속 참조되는 경향을 의미한다. (배열, 순차적 코드 실행, 프로그래머들이 관련된 변수들을 근처에 선언하는 경향)

##### 시간 지역성  
- 특정 자원들을 상대적으로 짧은 시간 안에 재사용한다는 것을 의미한다.  
- 한 순간 한 지점에서 특정 메모리 위치를 참조할 때 동일한 위치에서 가까운 미래에 다시 참조할 가능성이 높다.  
- 예) 순환(루프), 서브 프로그램, 스택, 계산이나 합계에 사용하는 변수  

##### 공간 지역성  
- 프로세스가 주기억장치의 어떤 위치를 참조하면 그 근처를 이후에도 계속 참조할 가능성이 높다는 것이다.  
- 상대적으로 가까운 위치에서 데이터 요소를 사용한다는 것을 의미한다.  
- 데이터 정렬과 1차원 배열의 요소 탐색과 같이 선형 액세스할 때를 순차적 지역성이라 한다.  
- 예) 배열 검색(순회), 순차적 코드의 실행, 근처의 관련 변수 선언 등

#### 스레싱(Thrashing)
![369](/assets/images/Pasted%20image%2020261023203630.png)
- <mark><strong>페이지 교체가 자주 일어나는 경우</strong></mark>
- 너무 자주 페이지 교체가 일어나는 경우를 말하는 것으로 어떤 프로세스가 프로그램 수행에 소요되는 시간보다 페이지 교체에 소요되는 시간이 더 큰 경우를 말한다.  
- 다중 프로그래밍의 정도가 점점 더 커지면 스래싱 현상이 자주 일어나게 되고 프로세서의 이용률은 급격히 감소하게 된다.  
- 프로세서의 이용률을 높이고 스래싱을 중단하려면 다중 프로그래밍의 정도를 낮춰야만 한다.  
- 스래싱 현상을 방지하려면 각 프로세스에 필요한 프레임을 제공할 수 있어야 한다.  
- 지역성을 이용하여 현재 지역 크기보다 적은 페이지 프레임을 할당하면 페이지 부재가 발생하는 원인이 될 수 있다.  
- 프로세서가 요구하는 최소한의 수보다 페이지 프레임의 수가 적으면 적을수록 페이지 부재율이 증가한다. 그러면 더 많은 페이지 부재가 일어나고, 프로세서의 효율은 떨어진다.

#### 페이지 부재 비율(PFF, Page Fault Frequency)
- 스래싱을 예방하는 직접적인 액세스 방법으로, 페이지 환경에서 프로세스의 실행을 측정하는 기준이 된다.  
- 페이지 부재 비율이 높다는 것은 프로세스에 더 많은 프레임이 필요하다는 의미이고, 페이지 부재 비율이 낮다는 것은 프로세스에 프레임이 너무 많다는 의미이다.
- 페이지 부재 비율이 증가하고 유효 프레임이 없으면 어떤 프로세스를 골라서 중지해야 한다.
- 프로세스를 중지하면 페이지 부재 비율이 높은 프로세스들에 프로세스에 할당된 프레임을 분배한다.
- 스래싱은 페이지 부재에서 발생하므로 페이지 부재 비율을 조절하는 것이 필요하다.

##### 페이지 부재 빈도
![Pasted image 20261023204034.png](/assets/images/Pasted%20image%2020261023204034.png)
- 빈 프레임이 있을 때 
	- 페이지 부재 비율이 상한 값을 초과하면 현재 프로세스에 프레임을 할당한다. 페이지 부재 비율이 하한 값 이하로 떨어지면 현재 프로세스의 프레임을 제거한다.
- 빈 프레임이 없을 때
	- 페이지 부재 비율이 상한 값을 초과하면 희생시킬 프로세스를 선택하고, 그 프로세스의 실행을 일시 중단한다. 현재 프로세스의 페이지 부재 비율이 하한 값 이하로 떨어지면 현재 프로세스의 프레임을 제거한다.  
- 페이지 부재 비율이 상한 값을 넘으면 프로세스에 다른 프레임을 더 할당하고, 하한 값보다 낮으면 프레임을 회수한다.
