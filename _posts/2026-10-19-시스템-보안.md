##### <strong><font color="#ff0000">윈도우 시스템의 주요 기본 그룹</font></strong>
기사 24.1
- <mark><strong>Administrators</strong></mark> : 도메인 자원이나 로컬 컴퓨터에 대한 모든 권한이 존재하는 그룹
- Account Operators : 사용자나 그룹 계정을 관리하는 그룹
- <mark><strong>Backup Operators</strong></mark> : 시스템 백업을 위해 모든 시스템 파일과 디렉터리에 접근 할 수 있는 그룹
- <mark><strong>Guests</strong></mark> : 도메인을 사용할 수 있는 권한이 제한되고 시스템 설정 변경 권한이 없도록 조치한 그룹
- Print Operators : 도메인 프린터에 접근할 수 있는 그룹
- <mark><strong>Power Users</strong></mark> : 디렉터리나 네트워크를 공유할 수 있고 공용 프로그램 그룹을 만들 수 있으며 컴퓨터의 표준 시간을 조정하는 등 일부 권한을 가지고 있는 그룹
- Replicator : 도메인에 있는 파일을 복제할 수 있는 권한을 가지고 있는 그룹
- Server Operators : 도메인 서버를 관리할 수 있는 권한(로컬 로그인과 시스템 재시작, 시스템 종료 등)을 가지고 있는 그룹
- <mark><strong>Users</strong></mark> : 도메인과 로컬 컴퓨터를 일반적으로 사용하는 그룹. 사용자 환경을 직접 만들 수 있지만 설정할 수 있는 항목에는 제한이 있다.

##### 비트로커, TPM
18.1 기사
- <mark><strong>비트로커(BitLocker)</strong></mark> 
	- Windows에서 제공하는 **드라이브 암호화 기술**
	- 노트북 분실이나 저장 장치 분리 등에 따른 데이터 유출 방지.
	- **TPM을 활용해 부팅 구성 요소의 무결성을 검증**하고 암호화된 드라이브를 보호할 수 있음

- **TPM(Trusted Platform Module)**
	- 암호화 키 등을 안전하게 저장하는 하드웨어 기반 보안 모듈. 
	- 부팅 과정에서 구성 요소의 무결성을 측정하고 검증하는 기능을 지원. 
	- 승인되지 않은 변경을 탐지하고 신뢰할 수 있는 부팅 및 보안 기능을 지원
- 하드웨어와 소프트웨어, 펌웨어 인증을 검사하는 전용 칩. TPM은 승인 없는 변경을 감지했을 경우 PC는 제한된 모드로 부팅되어 잠재적인 공격자의 악의적인 행위를 차단한다.
	- **펌웨어(Firmware)** : 하드웨어를 제어하기 위해 장치에 내장된 소프트웨어 (BIOS,UEFI)

##### Pass the Hash 공격
21.1 기사
- 윈도우 운영체제에서 Minikatz(미미카츠)와 같은 도구를 사용하여 등록된 사용자 계정의 LTLM 또는 LM(Lan Manager) 인증용 해시값을 탈취한 후 원격 서버나 서비스에 인증을 시도하는 공격 기법으로 패스워드 자체를 알지 못해도 접속 인증에 성공할 수 있다.

<mark><strong>Pass the Hash</strong></mark>
- 패스워드에 대한 해시값을 인증 시에 사용하는 환경에서 사용자(희생자)의 해시값을 획득한 후(탈취한 후) 이를 이용하여 인증을 시도하는 형태의 공격.
- 원격서버나 원격 서비스에 접속할 때 사용자의 실제 패스워드를 모르는 상태에서도 탈취한 사용자의 패스워드 해시값을 이용하여 인증을 시도한다.

Mimikatz(미미카츠)
- 윈도우 시스템에서 사용자 계정, 패스워드 등의 **자격증명(Credential)** 정보를 수집할 수 있는 도구

LM(LAN Manager) 해시
- Windows에서 사용하는 오래된 비밀번호 해시 방식으로, 비밀번호를 해시값으로 변환해 저장하는 데 사용.

LTLM(New Technology LAN Manager) 해시
- Windows의 NTLM 인증 체계에서 비밀번호를 기반으로 생성하는 해시값. LM보다 개선된 방식이지만, 여전히 해시값 탈취 및 재사용 등의 보안 위협이 존재.

##### 크리덴셜 스터핑(Credential Stuffing)
21.1 기사 25.4 기사 
- <mark><strong>크리덴셜 스터핑</strong></mark> 공격은 무작위(무차별) 대입 공격의 일종으로 공격자가 미리 확보해 놓은 사용자(희생자)의 로그인 자격증명(예: ID/Password 등)을 다른 사이트(서비스)의 인증 시스템 계정에 무작위로 대입하여 접속을 시도하는 공격 기법.

- **크리덴셜 스터핑(Credential Stuffing)**
	- 사용자의 계정, 비밀번호, 기타 여러 가지 신원 확인에 필요한 개인정보(자격증명, Credential)를 다양한 방식으로 탈취하여 사용자가 이용할 만한 시스템 및 사이트에 방문한 후 무작위로 대입(Stuffing)하는 공격 방식
	- 편의를 위해 한가지 ID와 비밀번호를 여러 시스템/사이트에서 사용하는 사용자의 취약서을 이용한 공격
	- 일반적으로 로그인 시 신원(신분) 확인 목적으로 사용하는 사용자 ID/비밀번호, 생체 정보 등이 크리덴셜에 해당.

##### 패스워드 크래킹 공격
**패스워드 스프레이**(Password Spraying) 공격
- (정의) 소수의(예 : 2~3개) 자주 사용되는 패스워드를 선택하여 다수의 사용자 계정에 순차적으로 대입해 보는 공격 방식
- (목적) 한 계정에 대해 많은 비밀번호를 시도하지 않기 때문에 계정 잠금 정책을 우회할 수 있다

**역방향 무차별 대입 공격**(Reverse Brute-Force Attack)
- (정의) 무차별 대입 공격과 반대로, 하나의 패스워드를 고정한 채 다양한 사용자 계정(실존하거나 무작위로 생성한 계정)에 대입해 보는 공격방식
- (목적) 공격자가 사용되고 있는 패스워드 일부를 확보했지만, 해당 비밀번호를 사용하는 계정을 알지 못할 때 활용하는 방식.

##### 리눅스 시스템 컴파일 방식
23.2 기사
리눅스 시스템에서 <mark><strong>동적 링크<mark><strong>(Dynamic Link) 방식으로 컴파일한 실행파일은 실행 시 호출하는 공유(외부) 라이브러리 함수가 프로그램 외부에 위치하므로 공유 라이브러리 함수를 사용할 수 있도록 주소를 연결해 주는 테이블인 </strong></mark>PLT<mark><strong> 와 함수의 실제 주소가 저장되어있는 테이블인 </strong></mark>GOT</strong></mark> 를 참조한다

1. 리눅스 시스템에서 컴파일 시 정적 링크 또는 동적 링크 방식을 선택할 수 있다.
- 링크(link) : 프로그램 내에서 라이브러리에 있는 함수를 호출할 때 호출된 함수와 라이브러리에 있는 함수 코드를 연결해 주는 과정
- **정적 링크**(static link)
	- 컴파일 시 **정적 라이브러리**(예: /usr/lib 디렉터리에 있는 .a 파일)를 사용하여 실행 파일 내에 라이브러리 함수가 모두 포함되도록 링크하는 방식.
	- 정적 링크한 실행파일은 호출한 라이브러리 함수를 모두 포함하고 있기 때문에 동적 링크한 실행파일보다 파일 크기가 크다.
- <mark><strong>동적 링크</strong></mark>(dynamic link)
	- 컴파일 시 **공유 라이브러리**(예: /usr/lib 디렉터리에 있는 .so 파일)를 사용하여 프로그램 실행 시에 외부 공유 라이
	  브러리 함수를 동적으로 링크하는 방식

2. 동적 링크 방식으로 컴파일 된 실행파일은 실행 시 외부 공유 라이브러리에 있는 함수 주소를 찾아내는 과정이 필요하며 이 때 PLT와 GOT 테이블을 참조한다.
- PLT(Procedure Linkage Table) : 외부 공유 라이브러리 함수를 사용할 수 있도록 주소를 연결해주는 테이블
- GOT(Global Offset Table) : PLT에서 호출하는 resolve() 함수를 통해 찾아낸 함수의 실제 주소가 저장되어 있는 테이블

##### NTFS
25.2 기사
<mark><strong>NTFS</strong></mark> 파일시스템은 윈도우 NT 계열에서 기본 파일 시스템으로 도입되었으며 시스템 오류 발생 시 복구를 가능하게 하는 저널링 기능 및 파일 암호화, 접근제어(파일과 폴더에 소유권과 사용 권한 설정이 가능하고 ACL 제공) 등을 통해 보안, 안전성, 신뢰성 등을 제공한다.

**NTFS(New Technology File System)**
- 윈도우 NT 계열의 기본 파일 시스템
1. **대용량 파일 지원**
	- 최대 수 테라바이트 이상의 파티션과 파일 크기 지원
	- FAT32 파일 시스템의 4GB 파일 크기 제한을 극복
2. 보안 기능
	- **ACL**(Access Control List) 기반 세밀한 접근 제어 기능
	- 파일/폴더 별 권한 지정이 가능하며 **EFS**(Encrypting File System)로 파일 단위의 투명한 암호화 지원
3. **저널링**(Journaling) 지원
	- 시스템 변경 내용을 저널에 기록 후 반영하여 장애 발생 시 빠른 복구 가능
		- 저널 : 파일 시스템에서 발생하는 변경 작업을 기록해두는 기록 공간
4. 기타
	- 파일/폴더 압축 지원
	- 클러스터 크기를 최적화하여 작은 파일도 효율적으로 저장(디스크 공간 효율성)

##### 저널링(Journaling)
15.1 기사
- Ext2 파일시스템에서 사용하는 fsck(file system Check)의 시간이 오래 걸리는 단점을 보완한 파일 시스템 복구 기술
- 복구 시간을 단축하기 위해 **데이터를 디스크에 쓰기 전에 로그(log)에 데이터를 남겨** 시스템의 비정상 종료 시에도 로그를 사용해 **fsck보다 빠르고 안정적인 복구 기능을 제공**
- Ext2 파일시스템에서는 **파일 시스템을 복구하기 위해** 슈퍼블록, 아이노드 등을 모두 검사해야 했지만, 저널링 기술이 도입된 **Ext3 파일 시스템**의 경우에는 파일을 실제로 수정하기 전에 우선 로그에 수정된 내용을 저장하기 때문에 **로그만을 검사하여 속도와 복구 안정성을 향상**시킨다.

##### 버퍼 오버플로우 공격 (스택 오버플로우/힙 오버플로우)
17.1 기사 25.2 기사
- 버퍼 오버플로우 공격
	- 메모리에 할당된 버퍼 크기를 초과하는 양의 데이터를 입력하여 이로 인해 프로세스의 흐름이 바뀌게 되는 형태의 공격
	- <mark><strong>strcpy</strong></mark>(char * dst, const char *src) : src 문자열을 dst 버퍼에 저장한다. src 문자열 길이를 검사하기 않기 때문에 **스택 버퍼 오버플로우**가 발생할 수 있다.
	- **strncpy**(char *dst, const char * src, size_t len) : src 문자열의 len 만큼을 dst 버퍼에 저장한다. src 문자열의 길이를 제한할 수 있으므로 버퍼 오버플로우 공격에 안전하다.
	- 취약점을 제거하기 위해서는 입력 값의 크기를 제한하는 strcpy() 함수를 사용하거나 코딩 시 입력값의 크기를 검사해야 한다.
- <mark><strong>스택</strong></mark>(Stack) 버퍼 오버플로우 공격
	- 스택 영역에 할당된 버퍼 크기를 초과하는 양의 데이터(실행 가능 코드)를 입력하여 **복귀주소(Retrun Address)를 변경**하고 공격자가 원하는 임의의 코드를 실행하게 된다.
- <mark><strong>힙</strong></mark>(Heap) 버퍼 오버플로우 공격
	- 프로그램 실행 시 힙 영역에 할당된 버퍼크기를 초과하는 양의 데이터(실행 가능 코드)를 입력하여 **메모리의 데이터와 함수 주소 등을 변경**하여 공격자가 원하는 임의의 코드를 실행하게 된다.

##### 리눅스 /etc/<mark>shadow</mark> 파일
25.4 기사 25.2 기사
- 계정별 암호화된 패스워드 정보와 패스워드 에이징(aging) 정보를 저장하고 있는 파일로 관리자(root)만이 읽을 수 있도록 기본 접근 권한을 가지고 있음.
	- 패스워드 에이징(Password Aging) : 비밀번호의 사용 기간과 변경 정책에 관한 정보
- shadow 파일에 저장된 암호화된 패스워드 필드의 의미
	- <mark><strong>$ID</strong></mark> : 암호화에 적용된 일방향 해시 알고리즘 식별 ID
	- $Salt : 패스워드 암호화 강도를 높이기 위한 임의의(랜덤) 값
	- $Encrypted_password : 사용자 패스워드에 솔트(Salt)를 조합한 후 일방향 해시 알고리즘을 이용해 암호화한 해시값(암호화된 패스워드)
- 암호화된 패스워드를 저장하는 파일로 유출 시 해당 파일의 암호화된 해시값을 크래킹하여 패스워드를 탈취할 수 있으므로 비인가자의 접근을 차단하도록 소유자 및 접근권한을 관리해야 한다.
	- 해시 크래킹(Hash Cracking) : 해시값을 분석하여 원래의 비밀번호나 데이터를 알아내려는 것

##### 리눅스 PAM(Pluggable Authentication Module)
23.2 기사 25.2 기사
- PAM 설정 파일 기본 구조
	- 모듈 유형(Type) 제어방식(Control) 모듈명 및 인수
- <mark><strong>모듈 유형(Type)</strong></mark>
	- <mark><strong>auth</strong></mark> : 사용자 계정의 비밀번호(인증 정보) 검증 등 사용자 신원확인을 수행하는 유형
	- <mark>account</mark> : 사용자 계정의 유효성(계정 유효기간, 접근 허용 여부 등)을 검증하는 유형
	- password : 사용자 계정의 비밀번호(인증 정보) 설정 및 변경 조건을 지정하는 유형
	- <mark><strong>session</strong></mark> : 사용자 계정 인증 처리 전후에 수행할 작업을 지정하는 유형
- **제어 방식(Control)** : 모듈의 실행 결과(성공 또는 실패)에 따라 어떤 동작을 해야 하는지 결정
	- **requisite** : (필수 모듈) 인증 실패 시 즉시 인증을 거부한다.
	* **required** : (필요 모듈) 인증에 실패해도 나머지 모든 모듈을 수행한 후 최종적으로 인증을 거부한다.
	* **sufficient** : (충분 모듈) 선행 모듈이 실패해도 현재 모듈 인증에 성공하면 최종적으로 인증을 허용한다.
	* **optional** : (옵션 모듈) 인증 성공/실패 결과는 모두 무시한다.
	* **include** : 다른 PAM 설정 파일을 포함한다.

##### 리눅스 네트워크 서비스 보안 - TCP Wrapper , iptables
13.2 기사
- <mark><strong>TCP Wrapper</strong></mark> 은/는 네트워크 서비스와 관련한 트래픽을 제어하고 모니터링할 수 있는 UNIX 기반의 방화벽 도구로 외부의 TCP 연결로부터 특정 네트워크 서비스(예: Telnet, FTP 등)를 보호하기 위해서는 각각 허용 정책 파일과 거부 정책 파일을 통해 통제 정책을 수립한다. 이 도구는 서버에 접근할 수 있는 서비스와 접근을 허용할 IP 주소를 세부적으로 설정할 수 있는데 hosts.deny 파일은 명시적으로 접근을 거부할 때, hosts.allow 파일은 명시적으로 접근을 허용할 때 해당 파일에 서비스와 IP 주소를 등록한다.

- <mark><strong>TCP Wrapper</strong></mark> 도구 
	- 네트워크 서비스와 관련한 트래픽을 제어하고 모니터링할 수 있는 UNIX 기반의 방화벽 도구로 클라이언트의 IP 주소를 확인하여 시스템 관리자가 접근을 허용한 호스트에 대해서만 서비스를 허용하기 때문에 외부의 해킹으로부터 시스템을 보호할 수 있다.
	* <mark><strong>hosts.allow</strong></mark> 파일 : 서비스 접근을 허용할 호스트 정보(IP 주소, 도메인명 등)를 설정하는 정책 파일
	* <mark><strong>hosts.deny</strong></mark> 파일 : 서비스 접근을 거부할 호스트 정보(IP 주소, 도메인명 등)를 설정하는 정책 파일

- **iptables** 도구
	- 리눅스 커널 방화벽이 제공하는 테이블들과 그것을 저장하는 체인, 규칙들을 구성할 수 있게 해주는 도구로 규칙(룰) 기반의 다양한 패킷 필터링 기능을 제공한다.

**윈도우 서버의 계정 관리 방식**
Windows Server 운영체제에서 사용자 계정 관리방식은 워크그룹(Workgroup) 방식과 <mark>도메인(Domain) 방식</mark>이 있으며, 로컬 사용자 계정은 %SystemRoot%₩System32₩config₩<mark>SAM</mark>에 저장되며, 도메인 방식은 <mark>엑티브 디렉터리</mark> 데이터베이스에 저장된다.

2. <mark><strong>워크그룹(Workgroup) 방식</strong></mark>
	- 각각의 계정과 자원을 시스템별로 관리하는 방식으로 소규모 네트워크에 적합
	- "피어 투 피어"라고도 하며 전용 서버 없이 모든 시스템이 서버이면서 클라이언트 기능을 가지며 서로 동등하다.
	- 서버 관리자가 필요없으며 보안 관련 정보는 각 시스템의 로컬 디렉터리 데이터베이스(**SAM** DB)에 의해 관리된다.
		- SAM(Security Account Manager) : Windows에서 로컬 사용자 계정의 정보를 관리하는 구성요소.
	- Active Directory가 구축되지 않은 상태로서 다른 시스템에 접근할 때 수시로 엑세스에 필요한 사용자 계정과 암호를 요구한다
3. <mark><strong>도메인(Domain) 방식</strong></mark>
	- 모든 계정과 자원을 특정 서버에서 관리하는 중앙 집중식 방식
	- 사용자에게 적절한 사용 권한을 설정하면 사용자는 다른 컴퓨터에 자원을 지정한 대로 접근할 수 있다
	- <mark><strong>Active Directory</strong></mark> 가 구축된 상태에서 가능하며 기존의 Windows NT 기반의 도메인보다 확장된 기능을 제공한다.
