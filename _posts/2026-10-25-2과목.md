## 1. 데이터분석 기획의 이해
### 분석 기획 방향성 도출

#### 분석 대상과 방법에 따른 유형
- <font color="#ff0000">분석대상(What)</font>과 <font color="#ff0000">방법(How)</font>이 알려져 있는지에 따라 분류
![Pasted image 20261026204251.png](/assets/images/Pasted%20image%2020261026204251.png)
- <font color="#245bdb">네 가지 유형을 복합적으로 넘나들며 분석을 수행</font>
- 상향식 접근 방식은 문제 정의 없이 데이터를 탐색해 의미 있는 패턴이나 현상을 <mark style="background:#fff88f"><strong><font color="#ff0000">발견(Discovery)</font></strong></mark>하고, 이를 통해 <mark style="background:#fff88f"><strong><font color="#ff0000">통찰(Insight)</font></strong></mark>을 얻는 흐름으로 진행된다

#### 접근 방식에 따른 유형
![Pasted image 20261026204334.png](/assets/images/Pasted%20image%2020261026204334.png)

#### 분석 기획시 고려사항
- 가용 데이터 파악 : 분석의 기본이 되는 데이터 확보 및 파악
- 적절한 <font color="#ff0000">유스케이스</font> 탐색 : 기존에 잘 구현 되어있는 유사 시나리오 활용
- 장애요소에 대한 사전계획 수립 : 장애 요인 사전 파악 및 대응 전략 마련

### 분석 방법론
#### 분석 방법론의 구성요소
- <font color="#ff0000">절차, 방법, 도구와 기법, 템플릿과 산출물</font>

#### 분석 모델의 유형
- 계층적 프로세스 모델 : 단계(<font color="#ff0000">Baseline으로 관리</font>) → 태스크 → 스텝(단기간 수행 WorkPackage)
- 폭포수 모델 : 이전 단계 완료되어야 다음 단계 진행 (Top-Down)
- 프로토타입 모델 : <font color="#ff0000">일부분(프로토타입)을 우선 개발하고</font> 보완
- <font color="#ff0000"> 나선형 모델</font> : 여러 개발과정 거쳐 점진적으로 완성, <font color="#ff0000">위험요소</font> 제거 초점
- 애자일 : 짧은 개발 주기를 가지고 고객 피드백을 지속적으로 반영하여 반복적인 개발
	- <font color="#245bdb">계층적 프로세스 모델은 빅데이터 분석 방법론의 기반</font>

#### <mark style="background:#fff88f">KDD 분석 방법론</mark>
- <font color="#ff0000">비즈니스 도메인 이해 -> 데이터 선택 → 전처리 → 변환 → 마이닝(분석 실행) → 평가</font>
- 데이터 선택 : 원시데이터(Raw Data)나 DB에서 필요한 데이터 선택
- 전처리 : 이상값, 잡음 식별 및 데이터 가공
- 변환 : 변수 선택 및 차원축소
- 마이닝 : 알고리즘을 선택하여 분석 수행
- 평가 : 결과에 대한 해석, 결과가 충족되지 않으면 절차를 반복 수행

#### <mark style="background:#fff88f"><strong><font color="#ff0000">Crisp-DM 분석 방법론</font></strong></mark>
- <font color="#ff0000">업무 이해 → 데이터 이해 → 데이터 준비 → 모델링 → 평가 → 전개</font>
- <font color="#245bdb">'업데데이트모델평가전'</font>
- 업무 이해 : 업무 목적 파악, 상황파악, 목표 설정, 프로젝트 계획 수립
- <mark style="background:#fff88f"><strong><font color="#ff0000">데이터 이해</font></strong></mark> : 초기 데이터 수집, 기술 분석, <mark style="background:#fff88f"><strong><font color="#ff0000">EDA(데이터 탐색)</font></strong></mark>, 데이터 품질 확인
- <mark style="background:#fff88f"><strong><font color="#ff0000">데이터 준비 : 데이터 셋 선택 및 정제, 통합, 포맷팅</font></strong></mark>
- <mark style="background:#fff88f"><strong><font color="#ff0000">모델링</font></strong></mark> : <strong>모델링 기법 선택</strong>, <strong>테스트 계획 설계</strong>, <font color="#ff0000"><strong>모델 작성 및 평가</strong></font>
- 평가 : <font color="#ff0000">분석결과 평가, 모델링 과정 평가, <strong>모델 적용성 평가</strong></font>
- 전개 : 전개 계획, 모니터링 및 유지보수 계획 수립, 프로젝트 종료 보고서 작성, 프로젝트 리뷰
	- 평가 → 전개에서 <font color="#ff0000">위대한 실패</font>(업무 이해로 다시 돌아감) 발생 가능

#### <mark style="background:#fff88f"><strong><font color="#ff0000">빅데이터 분석 방법론</font></strong></mark>
![Pasted image 20261026204916.png](/assets/images/Pasted%20image%2020261026204916.png)
- 분석 기획
	- 비즈니스 이해 및 범위 설정 : SOW(Statement of Works) - 구조화된 프로젝트 정의서
	- 프로젝트 위험계획 수립 : <font color="#ff0000">회피, 전이, 완화, 수용</font>
	- <font color="#245bdb">'회전완수'</font>
- 데이터 준비
	- 데이터 스토어 설계 : 정형, 비정형, 반정형 데이터에 따른 효율적 저장소를 설계
- 데이터 분석
	- <font color="#ff0000">탐색적 데이터 분석(EDA)</font> : 기초 통계량 및 시각화를 통해 데이터 특성 파악
	- 모델링 : 분류, 회귀, 군집 등 알고리즘 적용

### 분석 과제 발굴
#### 분석과제 명세
- 분석과제 정의서 : 분석 계획서 수립을 위한 핵심 입력 자료
- 분석 활용 시나리오 : 분석 결과를 어떻게 적용할지 구체적으로 정의한 실행 중심 문서

#### 하향식 접근 방법
- 문제가 주어지고 해답을 찾기 위해 진행
- <font color="#ff0000">문제탐색 → 문제정의 → 해결방안탐색 → 타당성 검토</font>
- <strong><font color="#ff0000">문제탐색</font></strong>
	- 비즈니스 모델 기반 탐색 : <font color="#ff0000">업무, 제품, 고객, 규제와 감사, 지원인프라</font>
	- <font color="#245bdb">'지원인프라 업무 중에 고객이 제품을 규제와 감사 했다.'</font>
	- 발굴 범위 확장
		- 거시적 관점 : <font color="#ff0000">STEEP</font>(사회, 기술, 경제, 환경, 정치)
		- 경쟁자 확대 관점 : 대체자, 경쟁자, 신규 진입자
		- 시장의 니즈 탐색 관점 : 고객, 채널, 영향자
		- 역량의 재해석 : 내부 역량, 파트너 네트워크
	- 내/외부 사례 참조
		- 외부 참조 모델 기반(벤치마킹), 분석 <font color="#ff0000">유스케이스(과거 유사한 사례)</font>
- **문제 정의** : 비즈니스 문제를 데이터 문제로 변환하여 정의
- **해결방안 탐색** : 기존 시스템 활용, 시스템 고도화, 인적 자원 확보, 아웃소싱 등
- **타당성 검토** : 경제적 타당성, 데이터 타당성, 기술적 타당성

#### <mark style="background:#fff88f">상향식 접근 방법</mark>
- 문제 정의 자체가 어려울 때, 사물을 그대로 인식
- <strong>데이터를 먼저 탐색하여 패턴이나 이상 징후를 발견하고, 이를 바탕으로 마지막에 문제를 정의</strong>
- <font color="#ff0000">프로세스 분류 → 프로세스 흐름 분석 → 분석요건 식별 → 분석요건 정의</font>
- 상향식 접근법의 적용 방법 : <mark style="background:#fff88f"><strong><font color="#ff0000">비지도학습</font></strong></mark>, <font color="#ff0000">프로토타입 접근법</font>, <font color="#ff0000">디자인 사고</font>의 발산 단계

#### 혼합 접근 방법
- 발산 단계 : 상향식 접근 방법으로서, 가능한 방안들을 도출
- 수렴 단계 : 하향식 접근 방법으로서, 도출된 방안들을 분석
- ※ 디자인 싱킹 : 사용자 공감으로 시작해서 아이디어 발산/수렴 과정을 통해 발전하는 방식
	- 공감하기 → 문제정의 → 아이디어 도출 → 프로토타입 → 테스트

### 분석 프로젝트 관리 방안
#### 분석 과제에서 고려해야할 5가지 요소
- <font color="#ff0000">데이터 양, 속도, 데이터 복잡성, 분석 복잡성, 정확도/정밀도</font>
- <strong>정확도(Accuracy)와 정밀도(Precision)는 <font color="#ff0000">Trade-Off</font> </strong>관계(=서로 상충)
	- 정확도 : 모형의 결과와 실제 값의 차이가 작은 정도
	- 정밀도 : 모형을 반복하여 적용했을 때 결과가 일관되게 나오는 정도
	- 분석 안정성 측면에서는 정밀도가 중요하고, 분석 결과를 업무에 실제로 활용하는 측면에서는 정확도가 중요
- <font color="#245bdb">여기에서의 정확도와 정밀도는 3과목의 오분류표에서의 평가지표와는 다른 개념</font>

#### 프로젝트 관리 지식 체계 10가지 영역
- <u>통</u>합, <u>범</u>위, <u>시</u>간(일정), <u>원</u>가, <u>품</u>질, 인적<u>자원</u>, <u>의</u>사소통,<u> 리</u>스크(위험), <u>조</u>달(<font color="#ff0000">아웃소싱</font>), <u>이</u>해관계자
  - <font color="#245bdb">'이범통이 의자에서 시원한 조리품을 먹었다.'</font>

## 2. <mark style="background:#fff88f"><strong><font color="#ff0000">분석 마스터플랜</font></strong></mark>
### 마스터 플랜 수립
#### IT 프로젝트의 우선순위 선정 기준
- <font color="#ff0000">중장기 마스터 플랜</font>을 수립 위하여 <mark style="background:#fff88f"><strong><font color="#ff0000">ISP</font></strong></mark>를 활용
	- ISP(Information Strategy Planning) : 정보기술 또는 정보시스템을 전략적으로 활용하기 위해 조직 내·외부 환경을 분석하고 기회나 문제점을 도출해 시스템 구축 우선순위를 결정하는 중장기 마스터 플랜 수립 절차

##### 분석 마스터플랜 분석 과제 우선 순위 결정
- <mark style="background:#fff88f"><strong><font color="#ff0000">전략적 중요도</font></strong></mark> : 전략적 필요성(조직의 비전, KPI), 시급성(해결 지연 시 Risk)
- <mark style="background:#fff88f"><strong><font color="#ff0000">실행 용이성</font></strong></mark> : 투자 용이성(예산 확보, <mark style="background:#fff88f"><strong><font color="#ff0000">비즈니스 성과·ROI</font></strong></mark>), 기술(실행) 용이성(기술 구현 난이도)

##### 분석 마스터 플랜 <font color="#ff0000">적용 범위 및 방식 결정</font>
- <font color="#ff0000">업무 내재화 적용 수준</font>, 분석 데이터 적용 수준, <font color="#ff0000">기술 적용 수준</font>을 고려해 결정
#### 데이터 분석 프로젝트의 우선순위 선정 기준
- <font color="#ff0000">시급성</font> 관점
	- 비즈니스 효과(Return) - <font color="#ff0000">Value</font>
	- <mark style="background:#fff88f"><strong><font color="#ff0000">전략적 중요도·목표 가치(KPI)</font></strong></mark>
- <font color="#ff0000">난이도</font> 관점
	- 투자비용 요소(Investment) - Volume, Variety, Velocity
	- 데이터 획득·저장·가공 비용, 분석 수준·기술 역량.
  ![Pasted image 20261026205708.png](/assets/images/Pasted%20image%2020261026205708.png)
- 시급성 중심 전략 : 3 → 4 → 2
- 난이도 중심 전략 : 3 → 1 → 2
- <font color="#245bdb">시급성이 현재에 해당한다는 것은 시급성이 높다는 의미</font>

#### 데이터 분석 로드맵
- 데이터 기반 의사결정을 조직에 정착시키기 위한 중장기 계획
- <mark style="background:#fff88f"><strong>데이터 분석 체계 도입 → 유효성 검증 (<font color="#ff0000">파일럿 프로젝트 수행</font>) → 확산 및 고도화</strong></mark>

### 분석 거버넌스 체계 수립
#### <mark style="background:#fff88f">분석 거버넌스 체계</mark>
- 조직, 프로세스, 시스템, 데이터, 인력을 아우르며 전사 차원에서 분석 업무를 기획·관리·통제하는 체계

#### 분석 거버넌스 체계 구성요소
- <font color="#ff0000">조직, 프로세스, 시스템, 데이터</font>, 분석관련 교육 및 마인드 육성체계
	- 프로세스 : 분석 과제를 발굴하고 기획, 수행, 평가하기까지의 일련의 절차를 표준화한 것
	- 교육 : 구성원의 분석 역량을 높이고 데이터 기반 의사결정 문화를 정착시키기 위해 지속적으로 시행하는 활동
- <font color="#245bdb">'시조프로마인드데'</font>

#### 데이터 분석 수준 진단
##### <strong><mark style="background:#fff88f"><font color="#ff0000">분석 준비도</font></mark></strong>
![Pasted image 20261026205953.png](/assets/images/Pasted%20image%2020261026205953.png)
- 분석적 업무 파악
- 인력 및 조직
- 분석기법
- 분석 데이터
- 분석 문화
- IT 인프라
- <font color="#245bdb">'IT문데기인파'</font>

##### <strong><mark style="background:#fff88f"><font color="#ff0000">분석 성숙도</font></mark></strong>
![Pasted image 20261026210042.png](/assets/images/Pasted%20image%2020261026210042.png)
- <mark style="background:#fff88f"><strong>비즈니스(업무 프로세스)</strong></mark>
- <mark style="background:#fff88f"><strong>조직 및 역량</strong></mark>
- <mark style="background:#fff88f"><strong>IT 부문</strong></mark>
- <font color="#245bdb">분석 성숙도 진단은 CMMI 모형(5단계)을 기반</font>

#### <mark style="background:#fff88f"><strong><font color="#ff0000">분석 수준 결과 진단</font></strong></mark>
![Pasted image 20261026212608.png](/assets/images/Pasted%20image%2020261026212608.png)
- 준비형 : 데이터, 인력, 조직, 분석업무, 분석기법 적용 안되어 사전 준비 필요
- 정착형 : 인력, 조직, 분석업무, 분석기법 등을 제한적으로 사용
- 도입형 : 조직 및 인력 등 준비도는 높으나, 분석업무 및 기법 부족
- 확산형 : <font color="#ff0000">6가지 분석 구성요소가 모두 갖추고</font> 있으며, 지속적 확산이 가능
- <font color="#245bdb">'도준정확' 4사분면부터 시계방향(역순)으로 암기</font>

#### <mark style="background:#fff88f"><strong><font color="#ff0000">빅데이터 거버넌스 프레임워크</font></strong></mark>

#### <mark style="background:#fff88f"><strong><font color="#ff0000">데이터 품질 관리</font></strong></mark>
- 품질 계획 수립부터 검토·보증·개선까지 전 과정에 걸친 활동
- 정확성·완전성·일관성·적시성 등의 품질 기준을 정의하고, 계획-점검-개선의 사이클로 운영된다.
- 분석 모델의 정확도와 신뢰성을 확보하기 위해 지속적인 품질 검증과 성능 모니터링을 수행하는 예방적 활동이다.
- 데이터 품질 계획은 기본적인 품질 정책을 수립하고 이를 달성하기 위한 품질관리 기준을 수립하는 단계이다
- 데이터 품질 보증은 산출된 데이터의 품질 신뢰를 부여하기 위해 반복된 오류를 개선하는 등 품질관리 프로세스의 전반적인 점검 및 평가 활동이다.

#### 분석 지원 인프라 방안 수립
- 확장성을 고려한 <font color="#ff0000">플랫폼</font> 구조 적용 (중앙집중적 관리)
- 광의의 분석 플랫폼 : 분석 서비스 제공엔진, 분석 어플리케이션, 분석 서비스 API, 하드웨어, 운영체제
	- 광의의 분석 플랫폼은 협의의 분석 플랫폼에 운영체제와 하드웨어를 더하고, 그 위에서 동작하는 분석 서비스 제공 엔진, 분석 애플리케이션, 분석 서비스 제공 API까지 포함하는 개념
- <font color="#ff0000">협의의 분석 플랫폼</font> : <font color="#ff0000">데이터 처리 프레임워크, 분석엔진, 분석 라이브러리</font>
- <font color="#245bdb">광의의 분석 플랫폼은 협의의 분석 플랫폼 요소들을 포함하는 개념</font>

#### 조직 및 인력방안 수립 (DSCoE : 분석조직)
- <u>집</u>중 구조
	- 독립적인 전담 조직 구성 (<mark style="background:#fff88f"><strong><font color="#ff0000">중복 업무 가능성 존재</font></strong></mark>)
	- 전담 조직이 <mark style="background:#fff88f"><strong><font color="#ff0000">전사 우선순위에 따라 분석을 수행</font></strong></mark>
- <u>기</u>능 구조 
	- 해당 부서에서 직접 분석 (<mark style="background:#fff88f"><strong><font color="#ff0000">DSCoE가 없음</font></strong></mark>)
	- 전사적인 분석 관리가 여러움
- <u>분</u>산 구조
	- 분석 조직 인력을 현업 부서에 배치
	- 분석 결과를 신속하게 실무에 적용할 수 있음
